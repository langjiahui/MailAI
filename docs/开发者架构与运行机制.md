# MailAI 开发者架构与运行机制

本文档承接原产品界面中的技术说明。面向普通用户的设置页不再展示实现架构、技术栈和内部处理管线。

## 邮件处理流程

1. **账号上下文与同步**：恢复当前账号，通过 IMAP 增量或全量同步邮箱文件夹。
2. **结构化解析**：标准化正文、会话、身份认证、链接、附件及内嵌图片。
3. **本地安全检测**：联合规则、域名、URL 链路、附件静态分析和发件人画像。
4. **模型语义复核**：按需对脱敏文本、会话上下文和视觉内容进行复核。
5. **融合与分级处置**：输出证据和风险分，按观察、人工确认或自动模式执行。
6. **效率与改进闭环**：生成分类、摘要、待办和日报，并通过反馈完善审计闭环。

## 分层架构

- **邮件与身份层**：IMAP 收取、SMTP 发送、文件夹同步、系统凭据库和账号上下文。
- **本地编排层**：同步续传、MIME 解析、规则与策略、URL 链路、附件与视觉证据、发件人画像、会话上下文、处置熔断和回滚。
- **智能增强层**：文本及多模态模型，用于安全复核、分类、摘要、待办和写信辅助。
- **数据与体验层**：账号独立 SQLite、原始邮件、草稿、会话、审计记录及本地工作台。

## 设计约束

- 每个邮箱账号使用独立数据库和原始邮件目录。
- 本地规则优先，仅按需将脱敏内容发送至模型 API。
- 自动处置设有单批上限和熔断保护，处置结果可恢复。
- 误报、漏报与人工确认均进入审计闭环。

## 技术栈

FastAPI、SQLite、IMAPClient、SMTP、HTML、CSS、JavaScript、OpenAI 兼容模型 API。
