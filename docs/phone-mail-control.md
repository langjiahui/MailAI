# 手机聊天控制邮件

入口：设置 → 手机控制。优先提供个人微信扫码连接；钉钉配置位于下方可展开的连接区。两种渠道可以同时启用，各自保存聊天中的当前邮箱与回复预览。

## 微信

1. 获取二维码，用本人微信扫一扫并在手机确认；若手机要求验证码，在设置中填写。
2. 选择允许控制的邮箱，勾选启用，保存设置。
3. 显示已连接后，在微信机器人单聊中发送“帮助”。

采用腾讯公开的 iLink / ClawBot 通道协议，不需要企业微信或安装 OpenClaw。该实现为接入测试版：真实账号能否连接取决于微信版本及通道开放情况，不能视为已完成真实账号联调。不通过个人微信的非官方登录协议或模拟点击接入。二维码过期可重新获取，关闭设置页会取消本次扫码。重新绑定须先关闭连接。登录失效后需重新扫码。

协议依据：[腾讯微信通道协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)。该文档明确客户端协议不代表完整服务端契约；上线使用前需要用实际微信账号验证。

## 钉钉

需要组织中的应用机器人创建权限，填写 Client ID、Client Secret、组织 Corp ID 和本人 senderStaffId / User ID。机器人需启用 Stream 接收模式并发布到本人可见范围；普通钉钉手机客户端可以使用，无需为了本功能购买付费企业版。仅有个人账号而没有应用创建权限时，先使用微信入口。

[钉钉官方创建指南](https://opensource.dingtalk.com/developerpedia/docs/explore/tutorials/stream/bot/java/create-bot/)

## 基础指令

| 指令 | 行为 |
| --- | --- |
| 帮助 | 显示简短的常用指令入口 |
| 帮助 更多 | 显示按场景划分的帮助目录 |
| 帮助 邮件 / 待办 / 回复 / 附件 / 设置 | 单独查看对应场景的操作方法；钉钉附件页会提示通道限制 |
| 邮箱列表 | 仅列出已授权邮箱 |
| 切换邮箱 name@example.com | 切换本次聊天的邮箱，不改变电脑界面 |
| 查收邮件 | 提交指定邮箱的后台同步任务，完成后尝试回传结果 |
| 最新邮件 | 展示本机收件箱最近 10 封及最近成功同步时间 |
| 未读邮件 | 在最近 100 封中展示最多 10 封未读邮件 |
| 有什么新邮件？ | 查询上次当前聊天/邮箱查看后的新增及未展开来信，首次默认今天；给出数量、未读与高优先级数量 |
| 更多新邮件 | 继续上次范围的下一页，按新收取顺序每页最多 10 封 |
| 今天有什么重要的？ | 汇总今天高优先级来信与今天需关注的未完成待办，邮件和待办分别编号 |
| 今天下午两点之后的邮件 / 昨天09:30之后的邮件 | 查询明确时间到现在的来信；支持中文时间、半点和全角数字，不推测日期，不改变增量查看进度 |
| 梳理重要邮件 | 当前聊天邮箱近 30 天的高优先级收件，展示最多 10 封及已有摘要，不额外调用模型 |
| 看看今天待办 | 当前聊天邮箱今天到期、逾期、无截止日期及今天有提醒的未完成待办，展示最多 10 项 |
| 查看第一项待办 / 查看第一项原邮件 | 查看待办详情或对应原邮件，支持中文与全角序号 |
| 下一项 / 上一项 / 返回待办 | 沿用当前待办列表序号继续查看，完成和已移除项会标明状态 |
| 查看原邮件 / 回复这封 | 核对当前待办的来源邮件，回复仍需预览和确认编号 |
| 查看第一封 / 查看第 1 封 | 查看该列表中的正文，最多 2500 字 |
| 回复第二封：你的正文 | 创建回复预览，尚未发送 |
| 回复：你的正文 | 回复当前在聊天中查看的邮件 |
| 确认发送 预览编号 | 10 分钟内发送该回复，编号只能使用一次 |
| 取消回复 | 删除聊天中的待发送预览 |
| 状态 / 上下文 | 查看当前邮箱、当前邮件、列表位置、回复阶段与同步时间 |
| 下一封 / 上一封 | 在当前列表中翻阅，跳过已移除或隔离的邮件 |
| 返回列表 | 返回原列表，序号保持不变 |
| 继续 | 恢复有效的回复预览、当前邮件或上次列表 |
| 回复这封 | 进入正文输入步骤，下一条普通文本成为回复正文，先预览后确认 |
| 回复预览 | 再次查看有效预览和剩余确认编号 |
| 修改回复：新正文 | 替换完整正文并生成新预览，旧确认编号立即失效 |

“查收邮件”先反馈任务已提交，收取完成后再回传新增数量或失败提示。只订阅当前邮箱的后台任务，不另启同步线程。会话过期、任务超过 3 分钟、反馈繁忙或网络不可用时，主动回传可能无法送达；输入“状态”核对成功时间，或“最新邮件”查看本机列表。反馈失败不会重新执行邮件操作。中文数字（一、二、两、十等）和全角数字均支持，转换仅针对指令序号，不修改回复正文。序号对应最近一次列表；连续阅读沿用原序号，返回列表不会重新编号。有效操作刷新上下文时间，闲置 30 分钟后需重新获取；查看另一封、切换邮箱、刷新列表或修改权限会使已有回复预览失效；反复查看同一封仍保留预览。预览不会新增邮箱草稿。

流程上下文按渠道、绑定身份、单聊会话隔离，保存在本机 SQLite；包含当前邮箱、列表邮件 ID、当前邮件 ID、正在等待正文的步骤和待确认预览，不保存完整聊天历史。重启后可恢复未过期流程，默认不会重放操作。仅改变 AI 开关或重复保存同样的授权不会清空上下文；启用状态、身份、密钥或邮箱权限变更会使旧流程失效。账号切换清空列表和预览，防止跨邮箱引用或误发。AI 查询只附带当前序号、列表长度和是否有选中邮件等结构化信息；摘要和起草才读取明确选中的邮件。

## 微信附件与语音查询

流程：“查看第一封的附件” → “把第二个附件发给我”。已选中邮件可说“查看附件”。中文序号、阿拉伯数字和全角数字均支持。图片可说“预览第一个附件”，支持 PNG、JPEG、GIF、WebP、BMP；GIF 预览为静态首帧。其他格式以原文件发送，当前不提供视频播放、语音回复或交互卡片。

仅读取已授权邮箱中本机保存的原始邮件；不从聊天接受任意文件路径或自动下载正文中的远程图片。原始邮件最大 40 MB，单附件最大 20 MB，每封最多列出 50 个。附件编号绑定当时的邮件与文件元数据；切换邮箱、选择另一封邮件、记录改变或上下文到期后需重新查看附件。内容会上传到微信通道，文件请求不调用模型 API。

一次只传输一个附件。文件在内存中加密后上传微信 CDN，图片复用本地受限预览，处理与上传在后台进行。上传前及发送文件消息前复核授权，重复平台消息、重启或结果不明时不会自动再次上传。微信确认接收后反馈；没有看到文件时先核对聊天，再明确重新发送指令。该能力依据[腾讯媒体上传](https://github.com/Tencent/openclaw-weixin/blob/main/src/cdn/upload.ts)及[消息构造](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/send.ts)实现，仍需真实微信账号联调。

语音只处理通道已经提供的转写文本，支持明确的邮件、待办和附件列表查询；不新增语音识别服务，不下载或分析语音音频。无转写、意图不清时提示使用文字；语音不能确认发信、编辑回复或传输附件。识别有误时用文字更正。钉钉当前仍只接收文字，未接入附件传输。

## 可选 AI 辅助

“有什么新邮件”不判断人是否离开电脑。进度按渠道、绑定身份、聊天、邮箱隔离并持久化，聊天上下文闲置过期或重启不清除进度；“最新邮件”成功回传会建立增量起点，“未读邮件”、指定时间查询及仅筛选部分邮件的简报不会推进该进度。增量查询按本机邮件 ID 识别新收取的来信，包含延迟同步的旧邮件，回显的邮件时间仍为原邮件时间。超过 10 封时只推进到已展示的一页；“更多新邮件”保持这批查询的范围，分页期间的新来信由下一次“有什么新邮件”返回。查看进度仅在平台成功接受回传后推进，回传失败不跳过邮件，重复回调不回退进度。这表示平台已接受回复，不等同于已确认用户实际阅读。

每次新邮件查询和今日简报标明查询范围及最近成功同步时间；未同步、休眠或离线时，空结果仅代表本机记录，不声明服务器没有新邮件。不自动收取、不修改已读标记，也不额外调用模型；先说“查收邮件”可触发既有后台同步。

重要邮件沿用本机高优先级标记，重要程度不等同于安全结论；待办沿用小邮的今日筛选口径，包含未来截止但今天有提醒的事项，不受原邮件收取时间限制。两者排除已移除、隔离或待删除的来源邮件，不从邮件正文临时生成新待办，也不修改待办状态。待办 ID、当前项及来源邮件同样保存在流程上下文中；“返回待办”保持原序号，“看看今天待办”刷新内容和序号。查看原邮件后可继续回复、显式总结或起草回复，切换邮箱会清空旧待办上下文。以上基于本机已同步记录；可先“查收邮件”更新。

在对应渠道打开“AI 辅助”并保存，复用 MailAI 已配置的模型，不新增模型凭证或强制订阅。默认关闭；常用指令仍直接执行，简单别名如“看看最新邮件”无需模型。首次本人聊天会介绍帮助入口，每次列表、阅读或回复预览给出下一步指令。

- 自然语言查询例如“帮我看看第一封来信”：模型仅能转换为查看列表、未读、重要邮件、今天待办、指定序号正文、收取、状态和帮助，不解释发送、删除、任意收件人或账号切换。
- “总结第 1 封”：返回该邮件的 AI 摘要。
- “起草回复第 1 封：礼貌确认收到”：生成正文并创建预览；“起草回复：你的要求”使用当前查看的邮件。
- 模型只接收查询文字；仅显式总结或起草时发送所选邮件的主题和最多 6000 字正文、最多 1000 字要求。可能产生已有服务商 API 费用。
- 单次请求设为 8 秒且不自动重试，最多一个模型请求；不可用时提示改用常规指令。AI 不能生成发送操作或确认编号，不能改变 Reply-To 收件人。预览由本地创建，仍需本人输入一次性确认编号。

## 运行、发送与隐私

### 本地离线提示（微信）

每次启动或重连后的首次本人指令回复，会说明电脑须开机联网、MailAI 须运行。持续断线至少 30 秒后恢复连接，会尝试发一次恢复提示；5 分钟内不重复提醒。正常退出 MailAI 时尝试发送暂停提示，最多额外等待 1.5 秒，不因通知失败阻塞退出。

主动提示仅使用最近 30 分钟内本人聊天的上下文，不持久化该平台上下文令牌；过期、关闭控制、换绑身份或平台拒绝时不发送、不重试。首次启动尚无聊天消息、重启后缺少上下文时，在下一次本人指令回复中提示在线。突发断电、强制退出、休眠或断网无法保证即时提示；没有云端服务就不能在电脑离线时接收指令并回复。通知只报告连接状态，不自动收取或发送邮件；发信结果不明时须核对发件箱。

- 电脑须开机联网，MailAI 须运行；退出或休眠后无法保证手机指令即时处理。支持 macOS 和 Windows 的共用代码，Windows 打包包含连接依赖。
- 微信仅接受扫码本人；钉钉仅接受指定组织和指定用户。仅处理本人单聊指令，忽略其他用户和群聊；微信接收文字和附带转写的语音查询。仅提供上述明确的附件获取，不提供远程任意收件人发信、删除、Shell 或任意本机文件访问。
- 实际回复复用现有发信接口，保留收件人校验与本地高风险检查。回复默认发给原邮件 Reply-To / 发件人，不自动回复全部，也不携带附件。遇到高风险检查时在电脑端处理。
- 授权消息在执行前持久化去重记录；确认预览在 SMTP 前消耗，重复平台回调不会重复发送。发送结果不明时必须查看 MailAI 发件箱核对，不自动再次发送。
- 凭证仅保存在 macOS 钥匙串或 Windows 凭据管理器，无法保存时拒绝启用。渠道权限、消息结果及预览存于本机 remote-control.sqlite3，不含登录密钥。
- 邮件正文与回复会经过所选聊天平台，基础指令不调用大模型，开启 AI 的数据范围见上文。关闭连接停止受理新指令；已开始的 SMTP 操作会等待结果，不强行中断。
- 网络恢复时自动重连。微信批次只有在处理和回传完成后才保存游标，回传失败可重试；去重记录仍避免重复发信。
