# 邮件「更多」菜单与图标排查

状态：基于 v2.9.0 的兼容界面及交互修正，纳入 v2.9.1。正式发布状态以对应 GitHub Release 为准。

## 工具图标

高级搜索保留滑杆，应用设置使用齿轮，邮件「更多」使用横向省略号；保持原有入口、国际化标签、主题颜色和点击区域。

## 更多菜单

- 取消安全操作与自适应移入操作的横向分隔线，采用 8px 留白分组。
- 统一 232px 菜单宽度、40px 操作行、图文间距、圆角和较轻阴影；触摸设备最小行高 44px。删除项保留红色及独立间距，长文字允许换行。
- 收紧工具栏样式的选择器，避免按钮移入菜单后继续携带工具栏边框、字体和行高。空的自适应分组不留空间。
- 打开、调整窗口、滚动阅读区时校准位置，优先向下展开，空间不足时向上展开；限制高度并允许内部滚动。锚点离开阅读视口时关闭菜单。
- 支持方向键、Home/End、跳过禁用项；Esc 关闭并恢复触发按钮焦点；点击或焦点移动到其他控件时关闭。
- WebKit 的鼠标按下会把焦点给阅读区祖先，而不是按钮本身。忽略这一祖先焦点变化，避免在 click 之前移除菜单而吞掉操作。

新增 `tests/test_reading_more_browser.cjs`，覆盖两种语言、六种主题、三种窗口宽度、130% 放大、可滚动末项、点击提醒、切换邮件、空分组、禁用项和焦点恢复，已接入现有 Chromium/WebKit CI。测试使用隔离邮箱样本，不访问真实邮箱或发出系统通知。

## macOS 系统旧图标

以下为首次排查记录；后续已在同日完成不重启电脑的修复，操作方法见下方「通知旧图标处理流程」。

首次排查时，本机标准安装是 `/Applications/MailAI.app`，版本 2.9.0、构建 149。Info.plist 指向 `mailai-a61c4d47b5f5.icns`。包内 1024px PNG 与源码 SHA-256 完全一致；ICNS 解包出的全部十种尺寸均为新图标，全部不透明像素一致。旧式 16/32px 表示只有半透明边缘 RGB 在编解码后有差异，alpha 相同；其余八个表示逐像素一致。没有 Finder 自定义图标属性覆盖。

NSWorkspace 当前首选和枚举结果均只有 `/Applications/MailAI.app`，读取出的原生图标也是新的。Spotlight 元数据是 2.9.0。LaunchServices 原始 dump 仍有历史记录，包括五个旧测试包记录，但不能据此断定它们当前覆盖正式应用关联。

已对标准安装副本执行 force registration 和 mdimport，均正常返回。Apple [Launch Services 文档](https://developer.apple.com/library/archive/documentation/Carbon/Conceptual/LaunchServicesConcepts/LSCConcepts/LSCConcepts.html) 说明了图标来自应用包及重新注册机制；重新注册成功不证明每个系统界面已经刷新。

首次排查结合用户截图，证据更指向系统缓存，但当时尚未确认具体缓存环节，也未通过修复验收。当时没有清空通知数据库、改变 bundle ID、重新申请权限、强制重启受保护服务或重启电脑。此前提出的重启建议未经验证；后续通过下述流程解决了通知图标问题。启动器、电池菜单等其他系统界面不在本次最终验收范围内。

原生资源与关联证据见 `audit-2026-10-16/icon-registration/`。

## 通知旧图标处理流程

### 适用情况与已验证结果

适用于已安装应用包中的图标正确，但新产生的系统通知仍显示旧图标的情况。先核对安装资源，再处理系统缓存；不要仅凭 Dock 已更新就判断通知图标也已更新。

2026-10-16 实机验证环境：macOS 27.0.1（26A434）、MailAI 2.9.1（构建 150）、`/Applications/MailAI.app`、bundle ID `com.langjiahui.mailai`。

本次定位到两个环节：

- IconServices 的 `ISBundleIdentifierIcon` 按 bundle ID 读取时返回旧盾牌，`ISBundleIcon` 按安装路径读取时返回新 M。两者的资源提供者都指向当前安装包及新 ICNS，常规 NSWorkspace 查询不足以发现这个差异。
- 整体刷新 IconServices 缓存后，新进程按上述两种方式读取的图像逐像素一致，缓存 UUID 也相同；通知中心界面仍持有旧图标，重载该界面后，用户确认新测试通知显示新 M。

最终有效顺序是：**刷新系统图标缓存 → 重载通知中心界面 → 验证新通知**。本次未重启或注销电脑，未重启 MailAI，未删除通知数据库或修改通知权限；通知中心重载后，日志确认原有通知重新载入。

### 1. 核对安装包

在项目根目录执行，确认版本、图标文件及签名。若安装包本身仍含旧图标，应先处理构建或安装问题。

```sh
/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' /Applications/MailAI.app/Contents/Info.plist
/usr/libexec/PlistBuddy -c 'Print :CFBundleVersion' /Applications/MailAI.app/Contents/Info.plist
/usr/libexec/PlistBuddy -c 'Print :CFBundleIconFile' /Applications/MailAI.app/Contents/Info.plist
/usr/bin/codesign --verify --deep --strict /Applications/MailAI.app
/usr/bin/shasum -a 256 /Applications/MailAI.app/Contents/Resources/app/web/static/assets/mailai-app-icon-1024.png app/web/static/assets/mailai-app-icon-1024.png
```

最后一项只有在源码与安装版应使用相同图标时才应一致。还应实际查看 Info.plist 指向的 ICNS，不能只核对 PNG。不要运行解包测试副本来验证，否则可能增加同 bundle ID 的系统注册记录。

### 2. 备份当前用户的图标缓存索引

以下命令使用同一个终端会话。临时目录用于保存诊断快照、编译产物和日志；它不是通知历史备份，也不保证能恢复所有共享图标缓存。

```sh
MAILAI_ICON_WORK="$(mktemp -d "${TMPDIR:-/tmp}/mailai-icon-refresh.XXXXXX")"
MAILAI_ICON_CACHE="$(getconf DARWIN_USER_CACHE_DIR)com.apple.iconservices"
mkdir -p "$MAILAI_ICON_WORK/cache-before"
for name in store.index tint-color-registry.map __cache_info__; do
  if [ -f "$MAILAI_ICON_CACHE/$name" ]; then
    cp -p "$MAILAI_ICON_CACHE/$name" "$MAILAI_ICON_WORK/cache-before/$name"
  fi
done
printf '诊断目录：%s\n' "$MAILAI_ICON_WORK"
```

### 3. 请求 IconServices 刷新缓存

需要本机已有 Xcode Command Line Tools。使用此次实机执行的[原生诊断源码](audit-2026-10-16/notification-icon-targeted-refresh/executed-icon-cache-refresh.m)，向 IconServices 现有连接发送 `clearAllCachedItemsWithReply:`，完成回调签名为 `void (^)(BOOL, NSError *)`。

```sh
/usr/bin/clang -fobjc-arc -fblocks -framework Foundation \
  docs/audit-2026-10-16/notification-icon-targeted-refresh/executed-icon-cache-refresh.m \
  -o "$MAILAI_ICON_WORK/refresh"
```

仅在编译成功后执行：

```sh
"$MAILAI_ICON_WORK/refresh" 2>&1 | tee "$MAILAI_ICON_WORK/refresh.log"
```

**必须看到 `Refresh completion: success=1 error=(null)` 才继续。** 归档源码中的退出码只表示回调是否结束，XPC 错误也可能返回 0，因此不能仅凭退出码或命令执行完毕认定成功。遇到错误、超时、权限拒绝或接口不可用时停止，并保留日志。

该操作刷新系统图标缓存，影响范围包含其他应用图标，它们会按需重新生成。这是 macOS 私有框架的一次性维护方法，目前仅在上述环境验证；不是 Apple 公开稳定接口，也未加入 MailAI 启动或安装流程。不应假设其他 macOS 版本具有相同类、方法或回调签名。

### 4. 重载通知中心界面

缓存刷新成功后，在当前登录用户下执行：

```sh
/usr/bin/killall -TERM NotificationCenter
/usr/bin/pgrep -x NotificationCenter
```

系统通常会自动重新启动界面；第二条命令用于检查新进程，自动拉起有短暂延迟。本次 PID 从 755 变为 14714。通知中心和桌面小组件可能短暂消失再恢复。这一步仅重载显示界面，不删除其数据库；无需重启 `usernoted`、Dock、Finder 或 MailAI。

若进程无法重载，记录实际错误，不使用强杀受保护服务、关闭 SIP 或更改签名权限来绕过系统限制。

### 5. 用新通知验收

在 MailAI「待办 → 提醒记录 → 测试系统通知」发送一条本地通知。确认左侧图标已更新，同时检查通知中心原有记录和通知设置仍保留。测试接口成功提交并不等于横幅已经显示。

维护者也可使用已运行 MailAI 的本地接口，避免界面自动化的屏幕捕获影响提醒测试：

```sh
curl --fail --show-error --silent -X POST http://127.0.0.1:8787/api/task-notices/test
```

先确认 8787 是本机正式 MailAI 实例的端口；若有自定义端口应相应调整。该接口只发送本地测试提醒，不发送邮件或触发收信。以新通知的实际显示为验收依据，不要求历史通知全部重新绘制。

### 横幅或声音没有出现时

本次图标修好后的测试通知曾只出现在通知中心。系统日志给出了独立原因：

```text
muted by display state (displayShared)
Not playing sound ... isMuted: true, hasSound: true
```

MailAI 已请求 `sound`、`list`、`banner`，但 macOS 因屏幕共享状态抑制了打断提醒。该状态可能与界面验收的屏幕捕获有关，不能把它归因于图标缓存刷新。

结束屏幕共享、录屏或界面捕获后，再通过本地接口测试。本次 16:37:15 日志显示屏幕捕获结束；16:37:51 新通知日志显示：

```text
interruptionSuppression: none
canDisplayWhileCenterIsClosed: true
Playing notification sound ... for com.langjiahui.mailai
```

可用以下只读命令检查近期记录（日志可能含通知标识，分享前应脱敏）：

```sh
/usr/bin/log show --last 3m --style compact --info \
  --predicate '(process == "NotificationCenter" OR process == "usernoted") AND eventMessage CONTAINS[c] "com.langjiahui.mailai" AND (eventMessage CONTAINS[c] "sound" OR eventMessage CONTAINS[c] "displayShared" OR eventMessage CONTAINS[c] "canDisplayWhileCenterIsClosed")'
```

如果用户确实需要在共享显示器时弹出通知，可在「系统设置 → 通知 → 通知中心」中选择镜像或共享显示器时允许通知；这会让共享画面中的其他人可能看到通知内容，应由用户决定，不作为图标修复的默认操作。参见 [Apple 通知设置说明](https://support.apple.com/zh-cn/guide/mac-help/mchl205da693/mac)。没有 `displayShared` 时，再分别检查专注模式、MailAI 通知样式、声音开关和系统输出设备。

### 无效尝试与记录位置

本次以下操作未解决问题，不应重复作为已验证修复：

- 替换应用资源、强制注册、`mdimport`，或注销再重新注册 MailAI。
- 单独设置描述符 `ignoreCache`，或调用客户端 `ISIconCache.clear()`。
- 定点删除旧图标缓存项：系统拒绝，要求 `com.apple.iconservices.allow-add-store-data` 专用权限；记录没有被删除。
- 仅刷新整体图标缓存而不重载通知中心：新进程读到新图标，但实际通知仍显示旧图标。

不要删除 `group.com.apple.usernoted` 或通知数据库，不要改变 bundle ID 或重新申请权限。本次没有采用删除 `/Library/Caches/com.apple.iconservices.store` 的方案。旧图标单项删除权限被拒绝后，使用的是系统服务接受的整体刷新请求，没有伪造 entitlement。
