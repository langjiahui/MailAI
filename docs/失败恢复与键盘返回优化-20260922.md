# 失败恢复与键盘返回优化

## 改动

- 任务与发件箱的五类状态分别读取。任一读取失败时，明确指出未加载的部分，隐藏“状态正常”和空任务结论，保留成功加载事项的操作入口。重新加载会再次请求失败部分；轻量轮询不会把失败的提醒读取当作有效缓存。
- 附件中心区分加载中、读取失败、成功但无匹配三个状态。读取失败后输入搜索词或点击类型筛选不会把错误变为空结果；重新加载保留搜索条件、类型和打开时的邮箱。统计数字同步更新，避免旧的数字动画覆盖加载状态。
- 从小邮返回时恢复键盘焦点：并排模式回到选中邮件，小窗口回到正文阅读区；焦点变化不强制滚动。

## 验证

- 完整离线发布检查 150/150 通过：build/recovery-focus-release.log。
- 自动测试覆盖各状态接口单独失败、成功事项入口保留、失败后重试恢复、附件筛选期间错误保留、重试账号固定、关闭和重新打开后的过期响应，以及返回焦点。
- 隔离预览加入可选的故障注入文件，仅影响测试服务器。浏览器验证模拟连接中断后的提示、附件筛选后重试恢复（保留“交付”和表格筛选）、任务状态恢复，以及 1280 宽度返回邮件列表时恢复选中项和滚动位置 567、760 宽度返回正文时焦点为 reading-pane。
- 使用临时测试账号和模拟邮件，无真实邮件发送或模型调用。源码与前端 bundle 已更新，安装包未重建。
