# MailAI Android 移动端交互重设计

日期：2026-10-18。第二轮设计，替代首稿四 Tab 导航。用户要求参考 iOS「邮件」与 Foxmail 移动端，提炼适合 MailAI 的体验。

本轮是产品设计与可点击示意，没有实现 Android 应用或真实收发。继续遵守手机独立运行、iOS 暂缓、GitHub APK 更新、账号数据隔离的既定方向。界面变化不改变后台任务与安装签名限制。本轮仅改文档，无需修改产品版本号。

## 1. 参考来源与证据边界

研究材料包括 Apple 官方说明与 iOS 26 邮件截图，以及腾讯在 App Store 展示的 QQ 邮箱截图和功能说明。本次实际查看了 Apple 邮件列表/轻扫操作截图，以及 QQ 邮箱写信、文件和日程宣传截图；未在真机登录或声称完成这两款 App 的完整操作测试。商店截图只能证明所展示的设计，不等于每个版本/平台都完全相同。

## 2. 提炼到 MailAI 的设计原则

| 观察 | 取用的原则 | MailAI 的具体决定 |
| --- | --- | --- |
| Apple 邮件以收件箱标题、发件人、正文预览和邮件操作为中心 | 首屏优先服务于扫描和处理邮件 | 取消四个功能 Tab，邮件成为唯一主线，底部切换为当前页面操作 |
| Apple 的旗标、邮箱、选择与轻扫帮助整理邮件 | 组织与批处理都应有明确入口 | 邮箱总览集中放智能视图；列表“选择”和阅读菜单可操作，轻扫作为补充 |
| QQ 邮箱支持多账号；写信图中展示发件身份、附件等编辑工具 | 账号和附件不能成为隐藏的技术细节 | 回复使用原收件账号；写信展示发件人；附件放正文附近，以文件行表达 |
| QQ 邮箱文件截图显示名称、类型、大小等；插件扩展工作能力 | 信息完整，扩展功能按场景出现 | 附件行显示格式、大小、下载状态；待办从邮件进入，不占首页固定 Tab |
| Foxmail 强调简单与稳定 | 操作结果和恢复路径应明确 | 草稿保存、发送确认、归档撤销、回到原列表是核心体验 |

这些是设计判断，不是断言参考产品都有完全一致的行为。Apple 截图也包含联系人头像及类别；MailAI 首版选择弱化头像、默认“全部”列表，原因是优先中文邮件扫描效率，并避免在分类能力未验证时隐藏邮件。不上来复制完整类别系统，不复制苹果商标、图标或硬件外框。

## 3. 新的信息架构

```text
邮箱总览
 ├─ 所有收件箱 / 单账号收件箱
 │    ├─ 全部 / 未读
 │    ├─ 筛选 / 搜索 / 批量处理
 │    └─ 阅读邮件
 │         ├─ 小邮 → 摘要 / 风险解释 / 回复草稿
 │         ├─ 附件 → 下载 / 预览 / 分享
 │         ├─ 回复 → 写信 → 发送前核对
 │         └─ 归档 / 星标 / 待办
 ├─ 星标 / 待核查 / 附件邮件
 ├─ 草稿 / 待办
 ├─ 各账号文件夹
 └─ 设置
```

启动恢复上次有效收件箱；初次添加一个账号时直接进入该账号收件箱。多个账号可用所有收件箱，但读写操作始终携带原账号标识。退出编辑态、返回阅读、返回列表、返回邮箱按层级执行，遵循 Android 系统返回；不照搬 iOS 特有的全局导航行为。

## 4. 页面设计

### 收件箱：连续列表、稳定层级

- 上方导航为“邮箱 / 选择 / 更多”。标题用“收件箱”，次行显示账号范围和未读数。
- 主筛选仅保留“全部 / 未读”；星标、附件和风险筛选从底部筛选菜单进入。
- 行结构为：左侧未读点；发件人和时间；主题；一至两行正文预览；必要时显示附件或风险提示。
- 默认不在每封邮件上放字母头像、多个彩色标签和卡片背景；旗标或会话数量只在有意义时出现。
- 时间采用今天时间 / 昨天 / 日期；不用强制按天分组制造大量标题。
- 底部为筛选、搜索输入、写信。搜索范围随当前邮箱和筛选明确变化；正式版输入时展开搜索模式并显示范围，结果更新不重建输入框。
- 同步正常时用低干扰状态，离线/失败时显示可恢复的提示。大标题随滚动折叠，正式版下拉刷新。

### 邮箱总览：账户与工具集中

- 智能视图放上方，账号放下方；计数与实际查询范围一致。
- “所有收件箱”仅聚合展示，不合并账号数据库。
- 点账号可进入对应收件箱；完整版本账号展开包含草稿、已发送、废纸篓和服务器文件夹。
- 待办、草稿保留一级入口；设置位于该页右上。
- 自动分类、云盘和日历不因为参考产品有就立即扩充首版范围。

### 阅读：内容优先，操作就近

- 顶部返回、星标与更多；主题自然换行；正文不嵌套到厚重卡片内。
- 发件人、时间、收件身份分层显示；普通邮件可展开完整地址，风险邮件直接露出真实发件地址，不能把判别依据隐藏。
- 小邮默认是一条可展开入口，结果出现后可以收起。风险提示仅在有证据时显示，不能以绿色“安全”标签替代评估。
- 附件位于正文邻近位置，用文件名、类型、大小和状态展示；下载失败可重试，不自动预取所有大附件。
- 底部操作为归档、加入待办、回复；更多包含回复全部、转发、标记未读、移动及移入废纸篓等。原型只演示其中一部分，完整实现仍按首版范围执行。

### 小邮：当前任务内展开

- 阅读中打开底部面板，先说明当前邮件范围，然后给摘要与来源。
- “生成回复草稿”进入真实编辑路径，用户可修改，再自行发送。
- 在草稿中润色要先预览改动，允许保留原文；原型仅展示这一设计意图，不执行模型请求。
- 不在整个 App 常驻浮动角色、自动弹出的聊天窗或首页大型 AI 宣传卡。
- 无模型配置、无网、超时、结果不完整都不阻止基础收发。AI 必须满足前一版方案的数据授权要求。

### 写信：像一张可持续编辑的信纸

- 顶栏为取消、写信/回复、发送；收件人、发件人、主题为轻量分隔行，正文占主要空间。
- 抄送/密送可展开，正式版提供附件、图片与基本编辑工具；无需同时展示所有高级选项。
- 新建信件与回复草稿状态分开，避免沿用上一封信的收件人；编辑器重建后从持久化草稿恢复。
- 返回时有保存、放弃、继续编辑；发送前核对身份与附件。AI 不自动点击发送。
- “撤销发送”若未来提供，应明确是提交 SMTP 前的延迟队列，不能冒充服务器已接收邮件的通用撤回。

## 5. 视觉与 Android 适配

- 白色/深色中性背景，MailAI 绿用于可操作元素、选择和未读点；不把整页染绿。
- 手机主标题约 30–32sp，发件人 16sp，主题 14–15sp，正文预览 13–14sp；具体遵循系统字号缩放，非固定像素硬锁。
- 行高由内容和字号决定，提供紧凑/舒适与一行/两行预览，不以截断正文或缩小字体换取密度。
- 保留足够触控区域；原生实现按至少 48dp 验收。圆角用于搜索框、面板与附件，不把每行邮件变成独立圆角卡片。
- 底部工具条避让手势区域；键盘出现时只保留编辑必需工具，不挤压正文；旋转、分屏和字体放大需验证。
- 借鉴层级和节奏，不仿制 iOS 的状态栏/灵动岛/系统弹窗；正式界面使用 Android 原生选择器、返回与权限流程。

## 6. 交互验收与原型范围

本轮可点击示意包含：全部/未读筛选、搜索、账号切换、星标、邮件阅读、完整地址展开、风险提示、小邮摘要示例、生成回复草稿、草稿保留、发送确认演示、选择多封邮件、标记已读、归档与撤销、加入待办并回到对应原邮件。

预览全部是合成邮件，AI 回答为固定示例；附件没有真实文件；不调用邮箱、模型或发送接口。草稿只在当前预览会话保留，不代表已经实现磁盘持久化。手势轻扫、原生文件选择、实际通知、完整账号文件夹及正式 UI 的动态标题尚未实现。

检查目标：浅色与深色、320px 窄容器、正文与控件不横向溢出、键盘可关闭面板、弹出面板时焦点停留在面板内、账号筛选不串号、待办指向正确邮件、归档可恢复、继续草稿保留内容。页面恢复不应被宿主状态回传打断。

正式 Android 开发前，使用这一版作为 UI 基线；后台与数据架构继续采用 [产品与技术方案](Android移动端产品与技术方案-2026-10-18.md)。不会因视觉参考调整已确认的手机独立运行要求，也不会将尚未实现的能力写成已上线。

## 7. 第三轮修订：克制的界面与完整的操作反馈

根据用户对星芒图标和交互等待的反馈，本节优先于前文有冲突的视觉描述。

### 视觉约束

- 移除星芒、魔法棒、机器人等装饰性 AI 符号。小邮采用“小邮 / 整理要点”的轻量文字按钮，写信采用“润色文字”。
- 阅读页移除默认头像、助手入口上下双分隔线、底栏多余图标；归档、待办、回复使用直接可理解的文字。仅保留返回、更多等少量通用符号。
- 通过主题、发件人、正文的字号、字重、留白建立层级。使用中性纸色、低饱和墨绿与轻表面色；减少描边、彩色标签和重复圆角容器。主操作“回复”保留稳定的实色按钮。
- 附件用文件名、类型、大小和下载状态表达信息。状态不能只依赖颜色；少画线不等于隐藏风险、焦点或选中状态。

### 每次操作的状态链

以下时间是实现目标，需在真机上验证，不是网络服务承诺。触摸按下时即时给出表面色与轻微压下反馈，目标在 100ms 内可感知；页面推进约 210ms、底部面板进入约 220ms、退出约 150ms。结果可用就展示，正式版不为播放动画而故意等待。

| 操作 | 即时反馈与等待 | 完成 | 失败、取消或返回 |
| --- | --- | --- | --- |
| 打开邮件 | 列表按压反馈；内容按导航方向过渡；本地正文先显示 | 稳定阅读，不整页闪烁刷新 | 无缓存时给内容占位与重试；返回恢复列表位置 |
| 整理要点 | 原邮件留在背景；面板立即显示当前邮件范围、正在整理及停止；收到文字逐步显示 | 显示完成、来源、起草回复与待办；同封邮件结果可再次直接查看 | 停止后标注未完成，禁止把部分内容当完成结果；失败保留原文，原位重试 |
| 起草回复 | 先显示正在起草；禁止重复请求 | 先预览，点击“使用这份回复”才填入编辑器 | 可保留原文；关闭/换邮件取消任务，迟到结果不得填入其他邮件 |
| 附件下载 | 立即显示连接状态；有总字节数时显示真实进度 | 显示可打开/分享状态 | 取消、失败、重试分别明确，不虚构百分比；无总量时只显示状态 |
| 编辑与保存草稿 | 输入不停顿；就近显示保存中 | 本地持久化完成后才显示已保存 | 保存失败保留编辑内容，提示重试，不静默丢失；离开页面不能覆盖新内容 |
| 发送 | 校验定位缺失字段；确认后显示阶段并禁重复提交 | 服务端确认接受后显示发送结果 | 未提交时允许取消/重试；提交后结果不明时显示“发送结果待确认”，检查发件状态，不盲目重发 |
| 归档、星标、待办 | 按压后即时更新可见状态 | 归档给撤销；星标给状态；待办给去向 | 同步失败保留恢复入口；撤销恢复原邮件和位置 |

超过约 2 秒仍在等待时，说明“仍在处理，可以停止”，不能无限转圈或编造进度。错误说明发生了什么、内容是否保留、下一步可做什么；不弹出技术错误码。原生触感只用于有意义的选择或结果，遵循系统设置，不让每次触摸都震动。减少动态效果开启时取消位移缩放，仍保留按下色、状态文字与结果反馈。

### 本轮预览已覆盖的过程与边界

已加入按下反馈、页面与面板过渡、小邮等待/逐步显示/完成/停止/重试、回复预览后使用、附件模拟进度/取消/重试、会话草稿保存提示、发送等待/连接失败/重试和归档撤销。设计控件可以切换“正常 / 稍慢 / 首次失败”，用于检查状态，不是产品设置。首次失败按操作和邮件分别模拟；重试后可成功。

预览首次展示用户截图对应的行程邮件阅读页，便于对照；正式产品的启动入口仍按前文收件箱规则。全部操作均为合成数据的本地演示，等待时长仅为演示用途；没有调用 AI、下载真实附件、持久化草稿或实际发送。润色、系统文件选择与真实同步仍只展示说明，尚未实现。原生震动、手势、键盘和辅助功能需在 Android 真机继续验收。

本轮浏览器检查已通过：立即出现整理状态、内容完成、停止后无迟到结果、首次失败后重试成功、慢响应提示、回复预览后使用、草稿保存提示及重新打开、发送连接失败后保留草稿并可重试、附件取消与失败重试、320px 深色模式无横向溢出、减少动态效果模式、无脚本运行错误。已查看浅色阅读页、结果面板及深色等待状态截图。这些检查仅覆盖原型，不代表 Android 真机或邮箱协议测试。
