# 自部署模型输出与连接提示

保留既有写信预览、用户确认后填入正文的流程，修复自部署 Qwen 将思考过程当作邮件正文显示的问题，并改进模型连接失败的提示样式。

## 模型输出

使用用户提供的 Qwen3.6-35B 服务和密钥做了最小测试，只发送虚构的会议通知要求，没有读取或发送实际邮箱内容。默认请求返回 HTTP 200，但思考文本与标签混在普通 `content` 中；关闭思考后，同类请求返回不含思考过程的中文主题与正文。没有将密钥保存到源码、测试夹具或记录中，也没有改动用户现有模型配置。

自部署和通用服务中的 Qwen3 请求默认加入 `chat_template_kwargs.enable_thinking=false`，保留扩展参数显式覆盖的能力。HTTP 客户端在普通 JSON 与 SSE 返回中分离保留标签的思考区、独立的 reasoning 字段及多段内容中的 reasoning 块；流式标签跨片段时先保留不完整标签，不将隐藏区发给前端。关闭标签前的已知思考前言和未结束思考区不会成为可填入正文。

写信提示明确只返回最终邮件内容，并保持写作要求的语言。结构化主题、正文和落款分离沿用原逻辑；非流式返回达到长度上限时也不作为完成草稿处理。实际生产写信流式路由通过自有模型验证，最终主题与正文包含周五下午 13:00、802 会议室，所有预览 delta 与完成事件中均无思考标记或前言。

## 连接失败提示

错误区域改为圆角卡片，使用当前主题的表面色与分隔线混合少量红色。保持 1px 细边框和轻微内高光，去掉粗红边，以错误图标、加粗标题和低饱和淡红底突出状态。明暗模式分别使用适当的错误强调色，正文保持当前主题的正常文字色。

展示明确的失败原因与处理建议，401 场景提示核对 API Key 与服务地址是否匹配。使用 `role=alert` 和即时播报，失败后聚焦并滚动到结果，保留输入且允许重试。加载、失败、成功与重新打开时统一维护状态，切换语言不会把失败提示还原成旧的“正在验证”。前端 bundle 和样式缓存版本已更新。

## 验证

- 输出过滤单元测试覆盖逐字符拆分标签、嵌套标签、未完成思考、普通正文与 HTML、多段 reasoning 内容、JSON 与 SSE 实际客户端。
- 写信结构、流式中断、截断输出保护、服务商请求适配、用量与资源限额回归通过；写信侧栏浏览器回归通过。
- 连接引导浏览器检查覆盖默认绿、黑白、宝武蓝各自明暗模式、细边框、文字与标题至少 4.5:1 对比度、焦点、保留输入、成功重试以及中英文切换。
- 测试通过独立偏好存储隔离每个浏览器，避免上一轮引导完成状态污染首次进入场景。浏览器测试只调用本地隔离夹具，不调用真实邮箱或模型。

系统级安装包尚未重新构建或安装；本次完成源码、前端资源与实际模型返回格式验证。
