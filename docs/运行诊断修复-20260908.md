# 运行诊断修复

旧版诊断中的邮箱、SMTP 和 AI 模型项目只判断地址、账号或密钥是否已配置，因此不能代表服务真实可用。模型设置页的“测试连接”可能已经失败，但运行诊断仍会因为存在 API Key 而显示绿色。

新版“开始检查”执行以下验证：

- 本地数据库：执行 SQLite `PRAGMA quick_check`，检查数据库能否打开及基本结构。
- 账号隔离：核对当前数据库与账号注册表映射，并检查可见账号是否错误共用数据库路径。
- 系统凭据库：区分已持久保存、仅本次运行有效和凭据缺失。
- 邮箱收信：真实登录当前 IMAP 账号并读取文件夹列表，不读取邮件正文。
- SMTP 发信：真实建立会话并完成认证，不发送测试邮件。
- AI 模型：使用当前已保存配置发送“只回复 OK”的最短请求，验证地址、API Key、模型 ID和响应结构。可能产生少量模型调用费用。
- 历史邮件初始化：读取实际任务状态，进行中显示警告，失败显示失败。

远程项目并行检查。界面明确标记“实测”或“本地”，并区分通过、警告和失败。返回结果不包含邮箱授权码、SMTP 密码、模型 API Key或邮件正文。

新增 `tests/test_live_diagnostics.py`，覆盖模型 HTTP 401、IMAP 超时、SMTP 实测成功、数据库与账号隔离检查以及敏感信息不泄露。完整发布检查 101/101 通过。
