# MailAI 成熟度与高可用问题修复

日期：2026-09-10

本轮修复《成熟度与高可用审查-20260910》中确认的 10 项问题。改动只作用于程序代码、测试和文档；验证使用临时数据目录、模拟邮件服务和虚构数据，没有连接或修改真实邮箱。

## 修复结果

1. **备份恢复的外部操作已冻结。** 完整备份在仍处于暂存区时，将排队或发送中的邮件改为“结果待确认”，删除待办、已读同步任务和邮件删除阶段。数据库安装后即使进程立即退出，也不会自动重放备份中的发送、删除或已读操作。
2. **同步身份加入 UIDVALIDITY。** 每个服务器文件夹持久化 UIDVALIDITY。同步发现代际变化时，旧 UID 记录转为本地保留数据，清空游标和旧远端任务，再导入新一代邮件；已读、星标、移动等远端修改遇到代际变化会停止并要求重新同步。
3. **邮件处理加入完成检查点。** 检测记录先以 `processing_complete=0` 保存，URL 证据、会话、待办和远端处置全部完成后才标记为完成。同步不再把“已有半条数据库记录”当作处理成功。
4. **链接追踪阻断本机和内网目标。** 首跳及每次重定向都只允许 HTTP/HTTPS、标准端口和公网 IP；阻断回环、私网、链路本地、保留及其他非公网地址。
5. **链接追踪改为显式逐跳。** 不再依赖会自动重定向的 `urlopen`。每次请求只处理当前一跳，记录 3xx、Location 和最终 200，严格执行跳数限制。
6. **草稿和已发送列表不再返回附件正文。** 列表查询去除 Base64 和重复的 `attachments_json`，正文只返回短预览；用户打开本地草稿或已发送邮件时再请求完整详情。已发送列表上限保持 500，草稿列表仍按本地草稿数量返回，但单条负载已受控。
7. **历史邮件按大小逐封下载。** 每批先读取 `RFC822.SIZE`，超过 50 MB 的邮件不自动下载；符合限制的邮件逐封读取，避免一次在内存中保留 50 封完整 MIME。
8. **模型安全结论采用严格类型校验。** `phishing`、`is_spam` 必须是 JSON 布尔值，`confidence` 必须是 0—1 数字，理由和证据必须是字符串列表。无效输出被忽略且不进入缓存，安全决策回落到本地规则。
9. **发送队列和应用实例增加跨进程锁。** 同一个数据目录只允许一个 MailAI 主实例；发送队列还使用独立文件锁作为第二层保护。第二个工作进程不能把仍在发送的任务误判为上次中断。
10. **处置模式按账号持久保存。** “仅观察／人工确认／自动处置”写入当前账号数据库，重启和账号切换后恢复。无效值回落到观察模式；保存先完成，界面才能收到成功响应。

## 额外收口

- 应用退出时统一停止调度器并等待发件后台线程，超时会留下明确日志供下次启动核对。
- 第二个应用实例未取得锁时直接停止启动，也不会清理正在运行实例的运行状态标记。
- 新增 `test_maturity_hardening.py`，覆盖邮箱代际、恢复冻结、处理检查点、SSRF、逐跳链接、模型结构、附件列表、历史下载、策略持久化和跨进程发送锁。

## 数据迁移

数据库初始化会自动增加：

- `sync_state.uid_validity`
- `emails.processing_complete`

已有邮件默认视为已完成；旧版本未记录 UIDVALIDITY 的文件夹会在首次同步时建立基线，不会直接丢弃本地邮件。之后检测到代际变化才执行安全重建。
