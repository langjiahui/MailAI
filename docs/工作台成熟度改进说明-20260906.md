# MailAI 工作台改进与验收

## 本轮改动

- 多邮箱使用独立请求上下文和独立同步状态；后台调度覆盖所有已连接邮箱。阅读、附件下载、草稿、发件、联系人、对话和备份均绑定操作所属邮箱，不再依赖修改全局邮箱配置。
- 统一收件箱与搜索支持分页加载，避免超过 1000 封后遗漏。风险和 AI 分类计数跟随其他筛选条件变化；分类按稳定顺序排列，空结果提供清除条件入口。
- 筛选收进列表上方，已应用条件以可移除标签显示。支持舒适/紧凑密度、邮箱别名和折叠；阅读区减少透明叠层，助手在宽窗口默认停靠右侧，也可切换浮动。
- 助手明确显示账号、查询范围和本次引用数量；按时间、重要程度与风险组合筛选，没有高重要程度邮件时不拿低重要程度邮件替代。切换账号清理旧对话与进行中的请求。
- 小邮采用简洁、自然的工作伙伴语气，区分工作重要程度与安全风险；引用必须来自本次检索。模型不可用时提供明确标注的本地结果；连接提前中断、输出截断会保留部分内容并允许重试。
- 风险提醒建立持久基线，补齐历史邮件不按新增风险推送，查看后不反复提醒；严重程度升级可再次提醒。支持全部、重要、仅高风险、关闭通知以及单会话静音。
- 批量标记和移动显示执行进度，分批处理；失败项保留并可单独重试。读状态、星标和移动的显式批量操作提供短时撤销，撤销前核对最新邮件状态，避免覆盖后续修改。
- 发信前先保存草稿，再进入 10 秒延迟发件箱。发送请求幂等，同一待发/待确认草稿不得重复入队；取消后保留草稿。
- 对 SMTP 回执丢失和进程中断，不自动重发；任务与发件箱显示“发送结果待确认”，用户核对后可确认已送达或未送达。恢复备份中的待发送任务也必须先核对。
- 任务与发件箱集中展示同步、发件状态、部分接收警告和提醒；阅读区提供加入待办、稍后提醒、单封总结和会话通知入口。通讯录增加分组，继续复用历史联系人与常用联系人。

## 验证

- 发布检查覆盖 46 个离线检查入口，包括 Python 行为回归、JavaScript 语法及客户端回归。
- 新增行为覆盖：两个线程的邮箱数据库隔离、2210 封统一收件箱分页去重、正文搜索分页、日期与高重要程度筛选、提醒基线/确认/升级、来源限制、模型流意外结束、重复发送防护、未知发送结果的人工确认、撤销连接失败恢复、带账号请求及附件资源路由。
- 隔离浏览器样例验证：组合筛选与分类计数、AI 本地回退与来源跳转、切换邮箱后的阅读区、发件身份、发送前检查、入队后撤销及草稿保留。未使用真实邮箱执行测试发送。
- 打包后的应用在独立空数据目录启动成功，健康接口正常，新增工作台资源校验值与源码一致；测试实例已退出。

## 使用边界

- AI 单次最多分析 20 封，并显示本次来源；可通过时间、筛选或选中邮件缩小范围，不宣称已阅读全文库。
- 统一收件箱支持跨邮箱阅读。批量修改需先选择一个具体邮箱，以免跨账号移动或误改；快捷键也遵守此限制。
- 稍后提醒依赖 MailAI 运行和界面轮询；完全退出应用时不会定时唤醒电脑。延迟发件同样在应用运行时执行。
- 发件“已送达/未送达”的人工确认应以服务器记录或收件人反馈为依据，不能仅凭网络错误判断发送失败。
- 本轮未进行真实邮件服务器、生产模型网关或安装后的长期运行验收；离线与模拟测试不能替代这些环境验证。
