# MacBook Air 顶栏显示优化

状态：源码已完成。实际 Chromium、WebKit 的隔离浏览器验证通过，本地测试 PKG 已生成并完成解包验证。用户 Air 安装后的实机显示尚待验证。

## 问题与改动

旧规则在顶栏容器宽度不超过 1240 CSS px 时同时隐藏全部按钮文字，因此即使 Air 的顶栏中间还有大量空位，也提前退化为纯图标；应用字号缩放进一步降低了可用 CSS 宽度。

现在保留搜索框的可伸缩性，在可用宽度 901–1240px 内仅压缩工具组间距和水平内边距。可用宽度 721–900px 才收起联系人、附件、待办与安全按钮文字；“写邮件”继续显示。可用宽度不超过 720px 时再收起写邮件文字，保证放大字号和窄窗口下所有原有操作均可到达。系统操作组继续保持紧凑图标样式。

调整基于现有容器查询，容器的实际宽度已受原生窗口控件和 body.zoom 影响；不使用设备型号或物理屏幕像素判断。修复旧媒体查询对按钮宽度、文字可见性的覆盖，使顶栏标签按同一组规则恢复；按钮配色继续沿用当前主题变量。没有改变用户的界面字号、窗口大小或系统显示缩放。

## 验证

新增 `tests/test_air_toolbar_browser.cjs`，使用临时账号测试服务，无真实邮件或模型调用。覆盖：

- 900、1100、1280、1366、1440、1470、1512、1618、1920px 窗口。
- 90%、100%、110%、130% 应用缩放。
- 简体中文 `zh-CN` 和英文；默认、黑白、宝武主题的浅/深配色。
- 足够空间时五个常用按钮文字保留；较窄时分级收起；搜索区与按钮不重叠；按钮边界不溢出；52px 原生标题区域高度不变。
- 写邮件与安全菜单可正常打开。

现有 `test_macos_workspace_browser.cjs` 另覆盖 macOS/Windows 桌面外壳和主要弹框，验证共享 CSS 的改动不挤出窗口控件。截图为临时模拟邮箱，不能当作用户实机截图。
