# 小邮：从读懂到下一步

本次的产品判断：员工主要需要减少遗漏、查找上下文和组织回复的成本；领导主要需要识别需要判断的事项、影响和缺失信息。这是设计假设，不是经过用户访谈验证的结论。

参考现有产品的两条方向：[Outlook 的优先级与解释](https://support.microsoft.com/en-us/outlook/copilot-outlook/prioritize-my-inbox)、[Gmail 的会话总结与回复起草](https://support.google.com/mail/answer/14355636?co=GENIE.Platform%3DDesktop&hl=en)。MailAI 此版侧重将本地依据直接衔接到现有操作，而非增加独立工具入口。

## 已实现

- 助手“对话 / 工作简报”两种视图，不覆盖聊天记录。
- 执行/决策是用户手动选择的关注视角，按邮箱保存在本机；不推测职位或权限。
- 本地整理待办安排、协作/决策线索、安全核验，说明范围和截断上限。
- 今日待办包含今天到期、今天提醒与近 7 天逾期事项；不将邮件请求自动变成任务。
- 协作线索来自近 7 天已同步收件箱的主题/摘要或高重要程度，不声称未回复或由本人负责。
- 单条/本组分析携带明确邮件 ID，输出责任、期限、下一步，或决策问题、方案、影响和缺失信息。
- 原邮件、回复编辑、添加待办、提醒均复用现有功能，用户点击后才执行；风险邮件不直接提供回复/创建任务快捷键。
- 支持“给我工作简报”“我先处理什么”“有哪些需要我决策的邮件”等无附加限定的问法；特定人名、日期的问题仍走原检索。

## 边界与后续

### 简报与待办融合（2000）

- 简报直接读取同一份待办记录，展示“今天先做”“等待反馈”“待你确认”和安全核验；不复制任务。
- 邮件线索通过统一安排窗口确认名称、执行/决策类型、截止或跟进日期及提醒后加入待办。已有任务直接编辑，已完成任务需明确恢复，避免反复生成。
- 等待反馈由用户主动设置，不根据邮件关键词推断；未来安排保留在待办中心，不挤占今日简报。
- 在简报或待办中心完成、改期、修改提醒，两个视图同步刷新。完成任务停止提醒；撤销时恢复尚未到期的提醒。
- 老版邮件提醒迁入关联待办，重复迁移不会重复创建；不同时间的旧提醒分别保留。提醒仅在 MailAI 运行时触发。
- 用户安排、修改或完成的任务不会被邮件后台重新分析覆盖；旧版任务保守保留。
- 忽略线索仅影响简报，可撤销，不删除邮件，也不隐藏安全风险。

当前不是语义级任务识别，不判断“是否欠回复”，不承诺跨系统完整性；同一主题可能仍有多个会话。简报无后台模型调用，不自动发送、不自动审批、不自动分配同事。模型不可用时保留来源与本地摘要并明确降级。

后续可在有可靠会话状态、明确用户授权之后增加：发出请求后的跟进队列、会前简报、周报草案、组织授权下的委派闭环。不能单凭关键词假装这些能力已存在。

## 今日时效规则（2100）

- 按任务截止/跟进日期及设备本地时区的提醒日期筛选，不按原邮件日期；今天提醒优先，即便原截止日期很早。
- 今天到期或提醒排在前面，最近 7 天（含第 7 天）逾期任务排在后面。
- 超过 7 天逾期进入默认折叠的“历史待整理”，不参与普通简报问答的默认来源；手动展开后仍可分析、改期或完成。
- 没有日期且没有今天提醒的执行任务、未来执行任务保留在待办中心；等待反馈任务在今日到期/提醒时进入今日区，否则保留等待队列，历史逾期归入历史区。同一任务不重复展示。
- 不删除、不自动完成历史任务；改期到今天后，原任务回到今日区。
