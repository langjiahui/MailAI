# MailAI 国内更新分发方案

日期：2026-10-19。状态：v2.10.1 已在 GitHub 与 AtomGit 正式发布，Windows/macOS/Linux 安装包及签名静态更新通道已验证；13 项云端检查、247 项离线门禁通过。macOS 完整安装包已从国内源下载并验证哈希、签名、版本和缓存复用。

## 建议路线

AtomGit 与 GitHub 并行检查；在经过校验的正式版本中选择较新版，同版本按响应速度自动选路。下载前向两个官方安装包入口分别请求最多 64 KB 范围，以当前可达性和速度选源，不查询国家或 IP 地理位置。失败后切换同一大小、哈希对应的另一源并保留下载进度。按当前用户偏好，暂不购买 COS、CDN 或域名。

维护者已注册 AtomGit 并创建普通公开仓库 https://atomgit.com/langjiahui2011/MailAI 。附件上传权限、单文件上限、总存储与流量额度必须在实际账号中确认，公开帮助未提供足够明确的发行版附件免费配额数字，不能承诺长期零费用或可用性保障。

2026-10-19 独立探测：无需令牌匿名读取 poco-ai/Agentero 公开发行版信息成功。对其中 119,982,600 字节的 AppImage 请求 bytes=1048576-1049599，返回 206，Content-Range 为 bytes 1048576-1049599/119982600，Content-Length 为 1024，内容类型为 application/octet-stream。实际内容域名为 file-cdn.gitcode.com。该探测只验证指定片段与匿名接口，并非完整文件下载，也不能代表所有大陆用户的连接质量。证据保存在 output/atomgit-evaluation/。

已上传 MailAI 自身 v2.9.5 的 Windows/macOS/Linux 安装包与校验文件，逐个匿名整包回读核对；macOS 80,035,011 字节安装包还完成从 1,048,576 字节开始的真实 206 续传及最终 SHA-256 验证。仅同步源码、镜像原样指向 GitHub 的 latest.json，都不能让安装包自动改走国内链路。

如果以后免费额度或平台稳定性不足，再评估自有域名加 COS/CDN。该方案不作为当前零额外支出路线的前置条件。

## 客户端行为

1. 检查更新并行访问 GitHub 与国内小体积清单，优先选择已验证的较新版本，同版本按实际响应速度选源；单个源超时不阻塞另一个可用源。缓存已验证的更新信息，重新联网后退避重试，避免每次打开都重复弹窗。完全离线时无法获知尚未下载的新版本。
2. 清单包含产品线、版本、平台、文件大小、SHA-256、可用下载地址及签名。客户端内置可信公钥，先验证清单签名再使用下载地址；不能仅信任镜像同时提供的文件与哈希。只提示高于当前客户端的版本，拒绝版本/地址/签名不一致。当前未实现 TUF 到期与防冻结协议；两源响应版本不一致时优先采用验证通过的较新版，慢源后台返回的更新结果也会缓存供后续检查使用。
3. 下载状态以版本、平台和 SHA-256 标识，保留部分文件与记录。断线、退出客户端、重启后继续下载。只在身份一致时续传，避免不同版本文件拼接。
4. 使用 HTTP Range 请求剩余字节，核对 206 和 Content-Range 的起始偏移及总长度。服务器忽略 Range 返回 200 时重新开始，不能直接追加。源失效时切换同一已验证发布物的其他地址，最终仍核对完整文件大小和哈希。
5. 短时网络故障自动重试，超过本轮重试次数后显示下载中断与进度已保留，用户再次点击更新时继续；区分下载未完成、完整文件校验失败、安装器启动失败。用户明确取消和文件损坏按各自策略处理。
6. 保留手动下载安装入口。旧版只认识 GitHub 的客户端，需要先通过可访问的下载安装链接完成一次升级，才能使用新国内更新源；只修改服务端清单不能保证旧客户端绕开其首次 GitHub 请求。

## 发布自动化

- 同一提交经过现有质量门禁，构建 Windows、macOS、Linux 安装包；Android 独立版本线及清单分别维护。
- 把同一份安装包分别发布到 GitHub 和AtomGit，使用含版本的平台路径，正式文件不可覆盖。
- 从 AtomGit 下载入口实际下载，校验大小与 SHA-256，再验证平台签名和版本。已验证维护者当前网络与 GitHub 云构建环境；电信、联通、移动的代表性大陆网络仍待独立覆盖，单机一次成功不能代表全部用户。
- 同步标签时校验与 GitHub 的提交一致，避免只读镜像仓库的标签延迟成为发布依赖。所有必需安装包就绪后，最后发布已签名的更新清单，避免用户先收到更新通知却没有可下载的安装包。
- 最新清单使用公开仓库 updates 分支的静态 latest.signed.json，经内置公钥重新验签；安装包使用公开网站发行版下载入口，避开共用匿名 API 的限流。临时签名直链不写入客户端；按版本读取不可变附件。更新通道推进后等待 CDN 刷新并核对实际匿名返回内容。
- 平台经典令牌不能限制到单一仓库，已向维护者说明并取得授权，仅开放项目和 Repository 读写；按维护者要求设为“长期有效”（2099-12-31）。同步脚本固定只操作 MailAI。令牌保存在仓库外受限文件及 GitHub Actions Secret，不进入客户端、更新清单或发布日志；下载端匿名读取公开发布文件。

## 最小验收

- GitHub 不可达时仍能检查、下载并安装国内更新。
- 下载到中途断网、关闭客户端、重启后能从已有进度继续。
- 返回短内容、错误 HTML、Range 不受支持或偏移错误时不破坏已有文件。
- 镜像切换、文件损坏、旧元数据及无效签名不能导致错误安装。
- 同一正式版的国内与 GitHub 文件哈希一致；客户端更新成功后以实际运行版本确认。

## 2026-10-22：国内 raw 清单 403 修复

- 实测 `raw.atomgit.com/.../raw/updates/latest.signed.json` 返回 HTTP 403，正文为“暂不支持预览”；文件确实存在且更新至 v3.4.0，官方文件 API 和不可变发行版附件均匿名返回相同签名字节。Android 独立 raw 清单当次可用，不能将问题归因于整个仓库或全部 JSON 文件被禁。
- 客户端保留静态入口，遇到网络异常、截断或 HTTP 拒绝时，一次切换到 `https://api.atomgit.com/api/v5/repos/langjiahui2011/MailAI/raw/latest.signed.json?ref=updates`。每次请求超时 3 秒，固定仓库、分支与文件名，不枚举版本、不依赖 GitHub、不在客户端保存令牌；两路均不可用时停止，由外层统一反馈。
- 两个入口共用 1 MiB 大小上限和内置 Ed25519 公钥；无效 JSON、无效签名和来源不符直接停止，不以另一入口掩盖内容错误。API 域名加入已有官方 GET 代理／VPN DNS 白名单，仍验证 HTTPS、目标公网地址与重定向。
- 通道发布端使用同一读取逻辑验证。静态入口 403 不再导致已有正确备用入口的通道误报失败；两路均拒绝访问时立即失败，临时网络异常仍有界重试，不覆盖历史标签和附件。Android 仅复用发布工具，其产品版本及客户端保持独立。
- 文档依据：[AtomGit 官方 raw 文件 API](https://atomgit-api-doc.atomgit.com/1.repositories/35.get_raw_file.html)。
- v3.4.0 及更早客户端不含备用读取；若当地无法访问 GitHub，需手动覆盖安装一次 v3.4.1，再使用修复后的自动更新。此修复不能从服务提供方外部改变旧 raw 路由的 403 响应。
