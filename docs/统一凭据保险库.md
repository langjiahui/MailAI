# macOS 统一凭据保险库

迁移完成后，MailAI 只需解锁一个钥匙串条目，就能恢复已迁移的邮箱密码、OAuth 令牌、模型密钥和其他连接凭据。正常修改密码、更新令牌不再改写多个钥匙串条目。

启动恢复和用户主动解锁使用 macOS 自带的 `/usr/bin/security` 读取主密钥，与较早版本的系统工具读取方式一致。授权绑定这个固定读取者，因此通常可以跨 MailAI 升级沿用，不再因为应用的临时签名变化而逐次要求授权。新建主密钥显式信任该系统读取者；已有主密钥的权限不被程序改写，首次切换到这条读取路径时，系统仍可能要求一次“始终允许”。钥匙串锁定、系统策略或用户撤销授权后仍可能需要确认。

后台查询继续通过原生接口禁用授权 UI，绝不启动可能弹窗的系统工具。启动恢复成功后，主密钥与解密数据仅在当前进程内缓存，已迁移的邮箱共用它。取消、拒绝或等待超时不会再通过另一种读取方式重复弹窗。主密钥通过原生 API 创建，密码不进入命令行参数；系统工具返回的数据仅在进程内解析，不记录到日志。

这种兼容方式信任系统工具作为读取者，不能视为把凭据严格隔离于同一登录用户下所有其他进程。系统工具可由该用户运行，与旧版的授权边界一致。需要把访问权限严格绑定到 MailAI 应用身份时，应配置稳定的开发者签名并使用应用原生读取路径。程序不设置“允许所有应用”，不修改系统钥匙串安全策略。

旧凭据分别受 macOS 钥匙串保护，不能用一次授权替代所有旧条目的首次授权。MailAI 在读取获得授权后将它迁入保险库；其他旧条目保持等待解锁，不会在后台集中弹窗。迁移失败会保留旧条目供后续重试，迁移不会扩大原有访问权限。

保险库位于用户应用数据目录的 `credentials.v1.enc`，采用 AES-256-GCM，随机主密钥只存于钥匙串 `MailAI / credential-vault-key:v1`。每次更新使用新的随机 nonce，文件仅允许当前用户读写，并以原子替换方式保存。密码、令牌、主密钥及凭据名称不会以明文写入该文件。

邮件备份、便携迁移包和安装包不包含保险库或主密钥。不要单独删除主密钥：失去主密钥后，加密文件无法解密，需要恢复钥匙串备份或重新配置凭据。损坏或缺少主密钥时，程序不会自动覆盖原有加密数据。删除凭据会保存删除标记，防止旧条目在后续迁移中恢复。

建议验收：首次为系统读取工具选择“始终允许”，完成旧邮箱迁移后重启应用，确认所有已迁移邮箱一起恢复；换装下一份临时签名预览包，验证无需重复授权。真实回归使用临时钥匙串、三个虚构邮箱和两个签名不同的父程序，确认同一保险库在两次启动中都只读取一次主密钥，均无需额外确认，加密文件保持不变。
