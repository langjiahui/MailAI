# MailAI 真实环境现场验收手册

> 目的：离线测试无法覆盖的场景，发布前用**专用测试邮箱**现场验证。
> 依据：`docs/成熟度与高可用问题修复-20260910.md` 末尾列出的待验收项。
>
> ⚠️ 全程使用专用测试邮箱和测试数据目录，**不要**用日常邮箱跑这些用例。

## 准备工作

1. 申请/准备一个不用于日常工作的邮箱，开启 IMAP/SMTP，记下客户端授权码。
2. 用独立数据目录启动，避免污染本机正式数据：
   ```bash
   # macOS/Linux
   MAILAI_HOME=~/mailai-acceptance ./venv-mac/bin/python run.py
   # Windows
   set MAILAI_HOME=D:\mailai-acceptance && .\.venv\Scripts\python.exe run.py
   ```
3. 向该邮箱发 5~10 封测试邮件（含 1 封带链接、1 封带附件），在面板完成一次完整同步。

## 用例 1：UIDVALIDITY 变化（邮箱重建）

**目的**：邮箱被服务端重建后，旧 UID 失效，程序应重建映射、不漏信、不错绑。

1. 记录面板中已同步的邮件数量与主题。
2. 在网页邮箱或服务器管理端：删除 INBOX 中全部邮件 → 删除并重建某个自定义文件夹（部分服务器会因此改变 UIDVALIDITY）；若无管理端，可用 imapclient 脚本删除/重建测试文件夹。
3. 重新发 3 封新邮件到该邮箱。
4. 面板点「立即拉取」。
5. **通过标准**：
   - 新邮件正常出现；
   - 日志出现 UIDVALIDITY 变化/重建相关记录；
   - 旧邮件本地数据未错乱（打开一封旧邮件，正文与主题对应）；
   - 没有把旧 UID 的移动/已读操作错误应用到新邮件上。

## 用例 2：同步中断网恢复

1. 向测试邮箱连续发 20 封邮件。
2. 面板点「立即拉取」，进度条进行中**断开网络**（关 Wi-Fi）。
3. 观察日志报错后，恢复网络，再点「立即拉取」。
4. **通过标准**：恢复后续传完成，最终 20 封全部入库，无重复、无丢失、无半解析记录（每封都能正常打开正文）。

## 用例 3：发送中强制退出

1. 在面板写一封发往测试邮箱自己的邮件，点击发送后**立刻强制结束进程**：
   ```bash
   pkill -9 -f "python run.py"      # Windows: taskkill /F /IM python.exe
   ```
2. 重新启动 MailAI。
3. **通过标准**：
   - 该邮件要么已真实发出（测试邮箱收到且本地显示已发送），要么留在草稿/发件队列中明确标记为未发送；
   - **绝不出现**：测试邮箱收到两封，或本地显示已发送但对方未收到。

## 用例 4：双击重复启动

1. 正常启动 MailAI。
2. 再次双击图标（或再跑一次 `python run.py`）启动第二个实例。
3. **通过标准**：第二实例明确提示已在运行并退出；第一实例不受影响，数据目录无损坏（重启后邮件、草稿、设置完整）。

## 用例 5：安装包覆盖升级

1. 安装上一个 release 版本的安装包，完成账号配置并同步一批邮件。
2. 不卸载，直接安装最新安装包覆盖。
3. **通过标准**：升级后邮件、账号配置、草稿、设置全部保留；版本号显示为新版本；自动更新功能可用。
