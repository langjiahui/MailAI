## 本轮实际修复

| 问题 | 修复与验证 |
| --- | --- |
| 空完整备份恢复失败；原文目录已移走时未进入回滚 | 空原文也创建暂存目录；同卷原子替换；分别记录原目录移走和新目录安装状态；合并恢复也先暂存。验证空备份恢复、目录切换中途失败、数据库写入失败和恢复安全快照。 |
| 本机接口缺少浏览器来源限制 | 校验 Host、Origin、Referer 与 Fetch Metadata，拒绝其他网页和其他本机端口调用 API，API 响应不缓存。包含正常本机、跨站、不同端口、恶意 Host、空/异常 Origin、IPv6 测试。此措施不隔离拥有本机权限的其他程序。 |
| 安全检查返回时可能覆盖新收件人、应用到新草稿或使用错误账号 | 检查绑定发件账号、草稿会话和完整内容指纹；先确认页面内容未变化再写回；保存后入队前再次核对。延迟检查时修改收件人已通过浏览器复现和回归。 |
| 已读请求结束时依赖可变的当前邮箱 | 请求和结果绑定原账号，避免修改另一账号中相同编号的邮件；同步更新行内已读状态。异步切换账号行为测试通过。 |
| 小邮新建或打开历史会话可能残留停止、重试、忙碌状态 | 中止旧请求、清空上一轮重试信息并复位控件及动画；旧响应不能写入新会话。 |
| 大截图解码时有多份全尺寸副本 | 串行化图片归一化，先缩小再进行 EXIF/透明通道转换；保留文件、像素、总量与动图限制。真实 2100 万像素长截图归一化测试通过。细小文字仍可能因缩放而需补局部截图。 |
| 小邮输入超过后端上限；不规范表格多余列被丢弃 | 输入限制与服务端 12000 字一致；长输入自动增高并内部滚动。表格额外单元格文本保留，不再静默丢失。 |
| 普通打包默认携带本机模型密钥及处置策略 | 共享密钥改为显式 `--include-api-key`；本次已按要求使用该选项。新安装强制默认仅观察，已保存用户策略不受影响。更新数据流与部署文档，纠正“模型不上云”的不准确描述。 |

3. 未验证全员并发模型服务的容量、费用额度、网络访问策略及可用性，也未将企业真实邮件用于外部模型压力测试。
4. 未做持续数日的睡眠唤醒、超大邮箱和弱网浸泡测试。已有超时、重试和恢复回归不等同于长期稳定性认证。
5. AI 输出不是事实保证，附件节选与图片缩放存在信息范围限制。敏感信息发送前需符合企业政策。
