# MailAI Android 移动端产品与技术方案

日期：2026-10-18。状态：设计基线；用户已确认开始开发，基础 Android 工程及开发 APK 已实现，具体交付与当前边界见 [Android 工程说明](../mobile/android/README.md)。

已确认需求：先做 Android，iOS 暂缓；手机独立连接邮箱，电脑关机仍可使用。首轮交付为设计和交互原型，不发布安装包。本文件沿用仓库文档约定；本次不修改 VERSION 或桌面发布产物。

## 1. 产品定位与边界

安卓版是独立邮件客户端：手机直接通过 IMAP/SMTP 连接邮箱，邮件、草稿、待办、分析结果保存在手机应用私有空间。基础收发不依赖 MailAI 电脑端、MailAI 云服务器或 Google Play 服务。

“独立运行”不等于“完全离线”：收发邮件需要网络；AI 默认由用户配置的模型 API 提供，手机直接请求，使用前说明发送范围；已有缓存邮件、草稿、待办可以离线使用。首版不承诺在手机上运行大型语言模型。

桌面和手机同时登录同一邮箱时，通过邮箱服务器同步邮件及服务端支持的文件夹、已读、星标等状态；MailAI 自定义标签、AI 分析、待办、小邮养成和本地归档不会自然同步。首版明确显示“此设备”，后续再设计加密导入和跨设备同步。服务端文件夹及星标支持以邮箱能力为准。

## 2. 架构调研结论

已检查当前工作区的实际实现和文档，工作区含大量现有改动；本轮只增加设计文档，原有改动保持原样。

| 现有实现 | 安卓复用方法 |
| --- | --- |
| `app/imap_client.py`、`app/smtp_client.py`、`app/parser.py` | 复用协议行为、异常分类和合成样例；移动端重做传输适配与 MIME 处理 |
| `app/db/sync.py` 的 UIDVALIDITY、同步游标和失败重试 | 复用语义与测试情形，不直接拷贝 Python 数据库访问实现 |
| `app/outbox.py`、`app/draft_lifecycle.py` | 复用发送状态与草稿保护原则，持久化到 Android 数据层 |
| `app/mail_idle.py`、`app/energy_scheduler.py` | 桌面线程和调度不能照搬；按 Android 生命周期、Doze 和任务配额重做 |
| `app/oauth_mail.py` | 复用账号行为；移动端需自己的 OAuth 注册、回调和认证适配，不能照抄桌面 loopback 流程 |
| `app/security/`、`app/llm/` | 优先提取规则数据、提示词、输出结构与合成回归用例；Python 专属和重型附件分析逐步迁移 |
| `app/web/static/` | 复用品牌、文案、图形素材与交互原则；不直接将三栏桌面页面作为手机版 |
| `app/release_update.py`、`scripts/create_release_manifest.py` | 保留 GitHub Release、校验、版本语义；新增 Android 清单字段与系统安装流程 |
| `docs/便携备份与跨平台迁移.md` | 后续兼容迁移参考；首版不宣称能导入桌面数据库或完整 v3 备份 |

当前项目是 Python + FastAPI + SQLite + Web UI；它不是已经具备移动构建能力的前端项目。Android 不会因生成一个 WebView 外壳而自动获得独立收发能力。

## 3. 技术路线决策

**推荐 Kotlin + Jetpack Compose 原生 Android。** Compose 是 Android 官方推荐的原生 UI 工具包；这个项目的主要难点是收发、任务恢复、凭据、附件与后台限制，原生方案便于直接控制这些行为。[官方文档](https://developer.android.com/compose)

| 路线 | 本项目收益 | 代价 / 结论 |
| --- | --- | --- |
| Kotlin + Compose | Android 平台能力直接接入；生命周期与状态恢复一致 | 首版推荐；将来 iOS UI 需要另做，领域模型可再评估共享 |
| Flutter | 将来双端界面有共享空间 | Python 邮件核心仍不能直接复用，后台与凭据仍需平台适配；iOS 暂缓时收益不足以优先 |
| WebView + Python 内嵌 | 部分现有代码可能复用 | Python 依赖、原生扩展、包体、后台进程及移动交互都需验证；不作为主线 |
| 手机连接电脑服务 | 复用现有后端较快 | 不满足已确认的独立运行需求 |

建议初始兼容基线 Android 10（API 29），这是产品提案，不是框架硬要求；若目标真机更旧，在技术验证阶段调整。compileSdk/targetSdk、Kotlin、AGP、Compose、Room 和 WorkManager 版本在建工程时核对稳定发布并锁定，不在本方案中猜测“最新版”。

数据库采用 Room/SQLite，账号独立数据库和附件目录；配置用 DataStore；密钥由 Android Keystore 保护，密码、token、模型 Key 用密钥加密后保存。Keystore 存储的是密钥，不是任意密码字符串；Room 本身也不提供数据库加密，不能对用户宣称已做全库加密。[Keystore 文档](https://developer.android.com/privacy-and-security/keystore)

IMAP/SMTP/MIME 库先通过实机验证再锁定：要求支持 Android、TLS/STARTTLS、OAuth SASL、中文 MIME、取消与超时，并检查许可。可研究成熟邮件客户端的协议行为，不未经许可复制其他项目代码。验证失败先调整邮件适配层，不推倒 UI。

### 推荐逻辑模块

```text
mobile/android/
  app/                应用入口、依赖装配、导航、发布渠道
  core/model/         邮件、账号、任务、风险、操作状态模型
  core/mail/          IMAP、SMTP、MIME、服务端能力适配
  core/data/          Room、账号目录、草稿、操作队列
  core/security/      凭据、邮件内容隔离、规则检测
  core/ai/            模型配置、流式请求、结果结构校验
  core/sync/          WorkManager、增量同步、重试、通知
  core/update/        版本检查、下载验证、系统安装
  feature/            邮件、阅读、写信、小邮、待办、设置
```

以上是职责划分；最初可以一个 Gradle 模块按包组织，避免在验证前制造过多模块。领域接口不依赖 Activity，平台差异留在适配层。iOS 仅保留未来选择空间，不作为首版交付或代码共享承诺。

## 4. 信息架构与手机交互

2026-10-18 第二轮设计：参考 Apple「邮件」和腾讯 QQ 邮箱移动端后，改为 **邮箱 → 收件箱 → 阅读 / 写信** 的主流程，取代初稿的四个底部功能 Tab。详见 [移动端交互重设计](Android移动端交互重设计-2026-10-18.md)。

默认打开上次使用的收件箱；左上“邮箱”进入统一收件箱、账号、文件夹、星标、附件邮件、待办、草稿和设置。底部保留当前页面的操作：列表页为筛选 / 搜索 / 写信，阅读页为归档 / 加入待办 / 回复。小邮按邮件上下文展开，设置不占主导航。

| 页面 | 主要内容与操作 |
| --- | --- |
| 首次进入 | 添加邮箱 → 验证 IMAP 与 SMTP → 首次同步；AI 可稍后配置；成功收到邮件后再说明通知用途 |
| 邮箱总览 | 所有收件箱、未读、星标、待核查、附件邮件、待办与草稿；下方按账户列出文件夹；右上设置 |
| 邮件首页 | 大标题、账号范围、未读数、全部/未读切换、连续单列邮件；底部筛选、搜索与写信 |
| 邮件阅读 | 主题、发件人完整地址、收件人、风险提示、正文、附件；底部回复/转发，小邮按需展开 |
| 写信 | 发件账号、收件人、主题、正文、附件；AI 润色保留原文；草稿保存状态可见；发送前检查身份与附件 |
| 待办 | 从邮件确认生成、本地提醒、已完成；点击回到来源邮件；提取失败不凭空生成事项 |
| 小邮 | 从阅读页或写信工具条展开，默认只使用当前邮件；摘要、解释风险和回复草稿均保留来源；未来跨邮件检索必须显式说明账号与范围 |
| 设置 | 邮箱、AI 服务、同步与通知、隐私与本地数据、主题字号、版本与更新 |

### 关键细节

- 邮件首屏优先显示发件人、主题、摘要和时间；风险用文字配颜色，不将“未发现风险”显示成“保证安全”。
- 列表默认减少头像和重复标签，用未读点、字重、两行正文预览和细分隔线建立层级；绿色集中用于操作和选中状态。
- 统一收件箱是显示聚合，数据库和后台操作仍按账号隔离；回复自动使用收到该邮件的账号，新邮件明确显示发件身份。
- 长按进入多选；滑动可归档/标记未读，但同样操作也必须有可见菜单入口。永久删除不做默认滑动动作。
- 返回保持列表筛选、滚动位置和阅读位置；写信退到后台、旋转屏幕、进程重建后恢复草稿。
- 单手主操作放下方；触控区域至少 48dp；适配系统返回、键盘遮挡、系统栏和大字体。
- 手机采用单列推入式阅读；平板/折叠展开后才使用列表 + 阅读双栏。
- 延续 MailAI 绿色品牌、浅色/深色和中文文案；首版小邮提供助手入口与轻量静态形象，养成和高频动画后置。
- 缺网时显示“离线 · 展示已下载邮件”；没下载的正文或附件明确提示，不显示空白假成功。
- 账号失效、同步中断、磁盘不足、AI 超时分别提示并提供对应恢复入口。
- AI 发信、删信、移动邮件不得由模型自行执行；首版只生成建议，用户确认后调用确定性业务流程。

## 5. 首版范围

### P0：可以日常试用的 Android 预览版

1. 通用 IMAP/SMTP TLS 邮箱及常用服务商参数预填；允许多个账号，首轮验证至少双账号隔离。
2. 邮件文件夹、增量同步、已读/未读、星标、缓存搜索；只搜索本地时标明范围。
3. 安全阅读纯文本和 HTML；远程图片默认不加载；附件按需下载、打开与系统分享。
4. 新建、回复、回复全部、转发、附件、本地草稿及持久化发件箱。
5. 基础风险提示：显示名/地址不一致、链接文本与目标不一致、危险附件扩展名等；带证据、可忽略、不过度承诺准确率。
6. 用户配置模型 API；摘要、翻译、润色、回复草稿；失败时保留原文并允许取消。
7. 基础小邮入口与邮件上下文问答；从邮件人工确认加入本地待办。
8. 尽力后台同步、通知、隐私设置、缓存清理及 GitHub 更新提示。

常用邮箱必须标注实际验收状态，不能因存在参数预填就宣称兼容所有服务商。首轮目标 QQ/163 和一个通用 IMAP 测试环境；Gmail/Microsoft 官方 OAuth 为后续小阶段，完成移动客户端注册、scope 和实机验证后再开放。企业邮箱禁用 IMAP/SMTP、需要管理员同意等情况单独提示。

### P1：使用体验与兼容性补齐

Gmail/Microsoft 官方登录、完整会话组织、更丰富的搜索、联系人补全、多封操作、自定义标签、本地待办提醒完善、稳定的加密导出恢复。针对用户的目标国产机型验证通知与省电策略。

### P2：高级能力

桌面 v3 迁移兼容、跨设备私有数据同步、深度附件分析、攻击链路、历史语义索引、自动隔离、小邮养成与主题兑换、超大附件云分享。

首版不提供精确到分钟的后台定时发送，不承诺后台全天实时收信，不自动永久删除邮件。公开稳定版需在预览版反馈后决定哪些 P1 项必须提升为发布门槛。

## 6. 同步、发送与数据可靠性

### 邮件同步

- 本地邮件主键使用内部 UUID；远端定位使用 `账号 + 文件夹 + UIDVALIDITY + UID`。Message-ID 只能作为关联线索，不能作为唯一主键。
- 每个账号串行协调写操作，前台刷新和后台任务共用锁/事务与同步状态，避免重复入库和游标跳过。
- 先同步信封和必要摘要，正文与附件按需下载。首次默认近 30 天、列表每页 50 封，是待实测调整的起点；用户可加载更早邮件。
- 游标仅在对应批次事务成功后提交；进程中断后从已提交位置恢复。UIDVALIDITY 变化时废弃旧远端映射，重新同步，冻结旧 UID 对应操作。
- 服务器已读、文件夹等状态最终以服务端为准；本地未提交操作用队列合并。处理另一客户端移动、删除或修改标记的情况。
- 删除采用移入废纸篓；邮件移动优先使用服务器支持的原子能力，退化路径需验证复制成功再执行后续步骤，禁止误 EXPUNGE 其他客户端标记的邮件。

### 发送状态

```text
草稿 → 待发送 → 发送中 → 已发送
                    ↘ 明确失败 → 用户重试
                    ↘ 结果待确认 → 核查后用户决定
```

SMTP 在提交邮件后连接断开时，客户端可能无法知道服务端是否已接收。此时不能盲目自动重发，必须显示“发送结果待确认”，保留 Message-ID 和操作记录，尝试核查已发送文件夹；核查无结果也不能视作绝对未发送。发送成功但归档失败时只重试归档，不能再次发信。内部幂等键避免双击重复排队，但不声称 SMTP 能提供端到端 exactly-once。

草稿自动保存与发送使用同一持久化记录；切换发件账号需重新确认身份。仅在服务端接收成功已确认后显示“已发送”。

### 后台策略

- 前台：进入应用、切换账号、下拉刷新时增量同步；可在可见期间使用 IMAP IDLE。
- 后台：WorkManager 的唯一周期任务，拟默认 30 分钟，可选 15/30/60 分钟；这是调度偏好而非到达时效承诺，Doze、网络与厂商省电可进一步延迟。周期工作最小间隔为 15 分钟。[官方说明](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)
- 长下载/用户触发的批量同步按需要使用有进度、有取消的任务；不使用全天常驻 dataSync 前台服务维持长连接。面向 Android 15+ 的应用在后台运行该类服务有时限。[官方说明](https://developer.android.com/develop/background-work/services/fgs/timeout)
- 重启后恢复可调度任务；系统强行停止应用、卸载、凭据失效时不承诺后台工作继续执行。通知权限被拒绝时仍可在应用内同步。
- 严格实时推送通常需要邮箱服务端配合或中继服务，应作为独立架构选择；FCM 本身不能替任意 IMAP 邮箱监听新邮件。本版不引入托管邮箱凭据的推送服务。

## 7. 安全与隐私设计

- 凭据密文、邮件数据库和附件保存在应用私有目录；首版明确数据库依赖系统文件加密和应用沙箱，不能把 Keystore 当作全库加密。
- 默认禁止邮件、凭据、草稿进入 Android 自动云备份及不受控设备迁移；Keystore 密钥不可迁移，未来恢复流程要求重新登录。显式导出另做密码加密与完整性验证。
- HTML 阅读使用隔离 WebView：净化 HTML、关闭 JavaScript、禁止原生桥、禁止任意 file/content 访问、默认阻止远程资源；链接交给外部浏览器并展示真实目标。[WebView 风险说明](https://developer.android.com/privacy-and-security/risks/insecure-webview-native-bridges)
- 邮件内 URL、重定向和远程图片访问要防 SSRF：校验 DNS/IP、阻止回环/私网和危险 scheme，并限制跳转、大小与时间。用户手工配置的邮箱/模型地址与邮件中提取的地址分开处理；如需支持内网企业服务，先补充仓库网络策略例外和测试，不暗中绕开现有要求。
- IMAP/SMTP 必须验证 TLS；不提供默认忽略证书错误的开关。端口/协议不匹配或服务端不支持加密时清晰报错。
- 首次启用 AI 明示服务商与发送范围；只发送当前操作所需内容；不把其他账号、全部邮箱或全部附件默认纳入上下文。
- 邮件正文与附件里的“指令”是待分析数据，不具备操作授权；模型返回必须符合预定结构，引用邮件来源可核查。
- 通知锁屏默认隐藏正文；日志不得记录密码、token、邮件正文、附件内容或完整模型请求。
- 附件文件名净化、防目录穿越、大小/解压限制；用 FileProvider 或系统文件选择器共享，临时授权；不默认申请全盘读写权限。
- API Key 由用户填写，不将任何公共付费 Key 或邮箱凭据编进 APK。

## 8. GitHub 分发与更新

首版采用自有 release keystore 签名的 APK，通过 GitHub Releases 发布。调试包使用独立 applicationId 后缀，正式签名私钥有加密离线备份；公开仓库及日志不能包含私钥。

更新路径：检查清单 → 展示更新内容和下载大小 → 用户确认下载 → 校验完整性/包身份/签名/版本 → 系统确认安装 → 重启确认新版本与数据库迁移成功。未安装或用户取消时保留旧版本。

推荐新增 Android 资产字段：platform、applicationId、versionName、versionCode、minSdk、ABI、url、size、sha256、signingCertSha256、notes。为保持旧桌面客户端兼容，新增字段而不改旧字段含义。若统一清单中的版本没有 Android 资产，安卓不得误报可安装更新。

- APK 应用 ID 固定；更新必须使用同一签名身份或经验证的官方密钥轮换流程，首版不做轮换。
- 客户端以自身内置的可信签名证书为校验基准，不能仅相信下载清单提供的新证书指纹；SHA-256 负责内容完整性，不单独证明发布者身份。清单签名可作为额外防护。
- versionName 遵守仓库 MAJOR.MINOR.PATCH；versionCode 是单独管理的递增整数，不直接使用可能重置的 workflow run_number，也不自动当作产品修订号。
- 普通用户安装要走系统确认与“允许此来源安装”设置，不承诺静默安装。[PackageInstaller 文档](https://developer.android.com/reference/android/content/pm/PackageInstaller)
- GitHub 不可达、限流或下载中断时可重试并进入官方发布页；首版不自动跳未知镜像。
- 正常覆盖安装保留私有数据，迁移需事务与回退；不引导用户卸载来完成普通升级，不支持随意降级数据库。
- Android 的地区开发者验证会影响安装体验。发布前按目标地区、设备和分发规模核对要求；不能宣称所有地区无限制免费分发。[官方说明](https://developer.android.com/developer-verification)

### 发布版本约定

建议沿用仓库统一产品版本和 `vMAJOR.MINOR.PATCH` 标签，安装包命名 `MailAI-Android.apk`；预览阶段先走 CI 测试构建，不擅自创建新的正式版本体系。若要安卓独立发布线，先补齐 CONTRIBUTING、发布门禁和两端更新策略。

正式发布前重新核对 GitHub 最新正式版本及全部变更。新增 Android 支持通常属于兼容新功能（MINOR），但最终按整次发布最高影响决定；本地 README 当前版本仅是调研快照，不据此预定下个版本。发布记录写明“基准版本、变更类型、目标版本、判断依据”，同步 VERSION、README、标签、APK 元数据和更新清单，不覆盖已发布资产。

## 9. 实施顺序与验收

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：技术验证 | Android 工程、合成邮件列表、最小收发实验、凭据和数据库恢复实验 | 模拟 IMAP/SMTP 验证通过；目标真机可运行；邮件库与构建链确定 |
| B：邮件闭环 | 添加账号、同步、阅读、附件、草稿、发件箱与操作队列 | 双账号隔离、断网恢复、SMTP 结果不确定和 HTML 隔离用例通过 |
| C：MailAI 能力 | 规则风险、摘要/润色/回复、小邮、待办、深浅主题 | AI 失败不破坏邮件和草稿；结果有来源；写操作有确认 |
| D：设备与发布 | 后台任务、通知、签名 APK、GitHub 升级与迁移 | 实机后台测试、旧包覆盖升级、错误签名拒绝、发布门禁通过 |

最初设计轮只完成 A 之前的产品/技术设计和交互示意。后续已按用户指示进入基础开发；上表仍是完整路线，不代表所有阶段都已完成。当前实现与验证记录见 Android 工程说明，真实邮箱和用户真机测试仍待开展。

### 必测情形

1. 手机联网、电脑关机时能收发；断网可读缓存和写草稿；进程被杀后草稿恢复。
2. QQ/163/通用 IMAP 的认证、文件夹与中文邮件；未通过验收的邮箱明确不列为支持。
3. 两个账号切换、通知跳转、搜索与 AI 上下文不会串号。
4. UIDVALIDITY 改变、重复 Message-ID、另一客户端移动/删除邮件、服务器中断均不误操作。
5. SMTP 明确失败、提交后断线、发送成功但归档失败分别走正确状态；重试不会重复发送。
6. 恶意邮件脚本、跟踪图、私网链接、异常附件不会调用原生能力或自动外联。
7. Android 10 基线设备及当前稳定 Android 设备；至少一台用户目标国产机型；无 Google Play 服务环境；省电、重启、通知拒绝、强制停止状态。
8. 360dp 小屏、大字体、深浅主题、软键盘、系统返回、旋转和折叠屏布局。
9. release APK 之间覆盖升级保留账号/邮件/草稿；下载截断、错误哈希、错误签名、较低版本被拒绝；取消安装后旧版仍可用。
10. 日志、崩溃报告、备份和构建产物不含凭据与真实邮件；开源依赖许可清单完整。

网络和破坏性操作优先使用合成数据及模拟 IMAP/SMTP；真实邮箱验证使用专用测试账号，发送、移动、删除不得用真实业务邮件代替回归测试。实施后按 CONTRIBUTING 执行现有发布门禁，并补充 Android 构建、lint、单元测试、设备测试与签名/升级验证；纯设计文档不运行应用全量发布门禁。
