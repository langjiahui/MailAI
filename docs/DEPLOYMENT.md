# MailAI 部署与内测说明

## 本次内测版本

`1.20260906.2700` 面向 macOS Apple Silicon（arm64），安装包写入 `/Applications/MailAI.app`。安装前保存草稿并退出旧版，建议先从「设置 → 数据与维护」备份每个账号。

本次试用包根据项目负责人的明确选择，包含当前模型连接及共享模型密钥；不包含开发者邮箱账号、邮箱授权码、邮件数据库、原文或会话历史。拿到安装包的人可能提取共享密钥，因此仅发给可信内测同事，不应上传公开下载地址。试用结束后建议轮换密钥，正式推广使用独立、限额、可撤销的企业网关凭据。

本机没有可用的 Apple Developer 签名身份，本包尚未完成 Developer ID 签名和公证。首次安装的系统信任提示、企业设备管理策略与其他 macOS 版本兼容性需要在目标机器验收；不要要求用户关闭系统安全保护。公开推广前应完成签名、公证和干净机器安装测试。

## 同事首次使用

1. 安装并打开 MailAI，在邮箱账号中添加自己的邮箱和客户端授权码；必要时由管理员确认服务器参数。
2. 检查收件和发件连接。新安装默认「仅观察」，不会自动移动服务器邮件；旧用户已保存的策略继续生效。
3. 等待首次同步，少量邮件验证分类、往来邮件和小邮分析。需要旧邮件时再拉取历史。
4. 使用测试联系人验证写信、回复、抄送、附件、撤销发送。接收状态需从真实收件端核对。
5. 多账号在左侧直接选择收件箱、已发送和草稿；设置中的账号页仅用于维护连接。

本地邮件、分析记录与原文按账号隔离保存在用户数据目录：macOS 为 `~/Library/Application Support/MailAI`，Windows 为 `%LOCALAPPDATA%\MailAI`。授权码优先使用系统凭据库，不可用时使用兼容本地存储。

启用 AI 时，必要的邮件内容、明确上传的图片和选中的附件内容会发送到所配置的模型服务，不是完全离线分析。图片不能保证自动脱敏，企业敏感信息必须遵守数据使用政策。模型结论可能出错，涉及金额、付款、账号、审批或截止日期时应核对原始材料。

## 可复现构建

- 普通 macOS 包：`scripts/build_macos.command`。默认不带模型密钥，由管理员后续配置。
- 明确包含共享密钥的内部试用包：`scripts/build_macos.command --include-api-key`。
- Windows 构建：`scripts\build_windows.bat`；仅在明确需要内部试用凭据时加 `--include-api-key`。
- 手动准备试用默认配置：`.venv-build/bin/python scripts/prepare_bundle_config.py --include-api-key`。生成文件只供打包，不要提交版本库或单独分发，打包后删除。

构建脚本提取白名单模型参数，不包含邮箱凭据。新安装的默认处置策略固定为仅观察，不能将开发机的自动处置策略直接传播给同事。

使用 Python 3.12/3.13、Node.js 和项目构建依赖。先运行 `scripts/check_release.py`；真实浏览器检查使用 `tests/workspace_preview.py` 隔离夹具和 `tests/prepublish_browser.cjs`，不能指向真实邮箱。PyInstaller 不能跨操作系统构建；本次 macOS 验收不代表 Windows 版本已验收。

## 内测反馈建议

先选择少量同事，覆盖企业邮箱与 QQ 邮箱、多账号、弱网、长时间同步、大附件以及睡眠唤醒。出现问题时记录版本、步骤、时间和截图；日志按企业规则脱敏后再提供。模型服务并发、费用限额与网络可达性需要在同事环境测试。
