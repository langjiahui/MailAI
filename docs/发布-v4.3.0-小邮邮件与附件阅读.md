# v4.3.0：小邮邮件与附件阅读

- 基准版本：v4.2.2（GitHub 最近已发布的 Web／桌面正式版本）
- 变更类型：MINOR
- 目标版本：v4.3.0
- 判断依据：新增整封邮件材料范围、持续附件会话，以及按服务商保存并验证的 PDF 读取方式，属于向后兼容的新用户能力；次版本加一，修订号归零，未达到编号上限。兼容的新增上下文数据表不构成破坏性升级。Android、iOS 独立版本不变。

## 用户可见变化

- 从邮件「问小邮」直接讨论正文与附件，不再要求先选附件再加入。材料清单按文件显示已读取、部分读取、未读取或已排除状态，单个文件失败不抹掉其他已读材料。会话固定邮件范围，浏览其他邮件不自动替换讨论对象；明确切换、排除和历史恢复均保留可见操作。
- 附件中心保留指定文件分析，可持续追问、补充、移除和恢复文件引用。输入区默认用紧凑文件名或数量展示，详情按需打开，不撑高输入框。
- 模型配置新增 PDF 读取方式：纯文字、按已启用图片能力逐页读取，或支持该协议的接口原文件直传。内网与第三方配置分别保存；使用合成 PDF 验证原文件能力。一次请求固定模型连接，分析途中切换服务商不改变该次材料的发送目标。
- 长文件依次读取页面或文字区段后综合，显示范围和进度。扫描页、图表、Office 排版和超限材料不作已完整读取的承诺；关键结论仍需对照原件。
- 关于与隐私页重新对齐版本和作者区域，区分产品名称、版本号及更新状态，更新内容按需展开，数据说明使用统一布局；适配默认、黑白、宝武蓝的明暗外观与中英文。
- 首次连接后先阅读邮件，AI 为可选配置；使用帮助显示实际完成进度，保留旧跳过和完成状态，补齐 17 个功能指南与读取 FAQ。
- 保留当前阅读工具栏、「总结邮件」「问小邮」及「AI 摘要」入口；未采用本轮放弃的工具栏和摘要移位效果图。

- 修复后台成长奖励刷新覆盖装扮兑换回执的问题；扣费与余额回执保持可见，成长、邮票和任务反馈继续更新。

## 数据与读取范围

原有邮件、账号、草稿、对话、事项背景、长期记忆、成长、装扮与偏好保持兼容。新增表仅保存当前邮箱下的会话材料引用和排除项，不将原附件字节、提取正文或 API Key 写入引用表。继续使用原有会话消息保存规则。引用每次重新读取并核对来源；指定文件校验内容摘要，跨账号不可使用。

整封邮件每轮最多 12 个附件，单个 10 MB、合计 20 MB，PDF 合计 100 页、附件文字合计 30 万字符。指定文件模式最多 3 个附件，合计 20 MB。正文沿用原模型输入字符范围并提示截断；Office 使用安全受限的结构化读取，不重算公式。原文件直传只针对支持指定 PDF 协议的模型接口，并受该接口上下文限制。

打开邮件对话、材料清单和本地提取预览不调用模型；发送问题后才开始分析。自动邮件分析与空闲记忆整理仍按已启用设置运行，所需内容可能发送至配置的模型服务，不能把本机存储理解为全部处理离线。

## 发布验证

候选源码、根 VERSION、README 和本记录定稿后，以固定提交执行完整离线门禁、凭据扫描、全部浏览器矩阵、原生平台检查和三平台候选构建。使用 `scripts/release_desktop.py --execute --head <候选提交>` 让候选构建与原始 full 并行；全部成功后才合并、核对同树产物、创建新标签、发布及验证国内镜像。正式附件和已发布历史标签不覆盖。
