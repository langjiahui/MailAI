## 二、MailAI 对照结论

### ✅ 架构层面已经规避（不需要担心）

| Foxmail 痛点 | MailAI 的证据 |
|---|---|
| 停更弃维护 | `VERSION` = 2.2.10，近 5 天连续发版（v2.2.7→v2.2.10）；`release.yml:19-21` 强制 VERSION 与 README 同步 |
| 历史邮件/附件自动消失 | 无任何 N 天留存逻辑；`DELETE FROM emails` 全仓仅 `trash_purge.py:112` 一处，且需 token + `confirmed=True` 双因子（`trash_purge.py:116-121`） |
| 老附件打不开 | 附件随完整 MIME 落 `.eml`（`parser.py:394-401`），预览与下载走纯本地读（`mail_read.py:133-149`），**断网、账号注销后仍可用** |
| 更新丢数据 | 数据在 `~/Library/Application Support/MailAI/data`（`paths.py:18`），与 app 本体解耦；迁移全为幂等加法，唯一 `DROP TABLE` 是可重建的 FTS 影子索引（`mail_search.py:30`） |
| 不支持导出迁移 | `.mailai-backup` / `.zip` 迁移包 + 磁盘上标准 RFC822 `.eml`，任何客户端可直接识别 |
| 草稿丢失 | SQLite + WAL，防抖自动保存 + 页面隐藏保存 + 退出钩子三层触发（`app.js:1607/7562/7571`） |
| 多账号混乱 | 每账号独立目录与库（`system_settings.py:357-362`），ContextVar 快照隔离（`account_context.py:40-51`）；统一收件箱每行带邮箱标签（`app.js:3165`），且仅在账号数 >1 时展开 |
| 联系人难用 | 分组增删改名、批量加人、拼音搜索、无姓名时邮箱兜底均已实现（`contacts.py:20-43`、`pinyin_search.py:21`） |
| 反垃圾/降噪 | 立身之本：46 条规则 9 大类（`security/policy.py:13-59`），LLM 仅在规则分 ≥35 时调用（`pipeline.py:359`） |
| 发送可靠性 | token 主键 + 草稿 id 二次校验去重、跨进程文件锁、失败原因回传（`outbox.py:65-81`） |

### 🔴 MailAI 同样中招（建议优先处理）

**1. 退出卡死 / 阻止系统关机 —— 与 Foxmail 第 3 号痛点完全同形**

- `desktop.py:573-578` `applicationShouldTerminate_` 在不满足条件时返回 `NSTerminateCancel`
- 兜底超时路径 `draft_lifecycle.py:28` 的 `complete(False)` 只 `show_window()`，**不设置 `runtime.quitting`**，下一次仍返回 Cancel → 可无限期阻止终止
- `mailbox_jobs.py:10`、`trash_purge.py:16` 的 `ThreadPoolExecutor` **全项目无任何 `shutdown()` 调用**；CPython `_python_exit` 会在解释器退出时同步 join worker，最坏等待 = 2 worker ×（LLM 300s + 链跟踪 165s）

**2. 收信延迟 —— 无 IMAP IDLE**

- 全仓无 IDLE 实现，`poll_once` 纯轮询，`config.py:83` 默认 `POLL_INTERVAL_SECONDS=300`（5 分钟）
- `mailbox_jobs.py:8-10` 线程池仅 2 个 worker，且**没有单账号看门狗**：2 个账号同时卡住 → 所有账号排队饿死

**3. 第三方账号登录 —— 只支持授权码，无 OAuth2 / Modern Auth**

- `imap_client.py:95`、`smtp_client.py:62` 一律 `client.login()`，全仓无 XOAUTH2
- `mail_providers.py` 只是服务器自动发现，无 OAuth 流程
- 风险在放大：微软已逐步停用 M365/Outlook 的 Basic Auth IMAP/SMTP，Google 也在收紧 → **Gmail / Outlook365 用户在不久的将来会直接登不上**，这会复刻 Foxmail 第 4 号痛点

## 三、建议修复顺序（按 ROI）

1. **macOS 终止路径**：让 `draft_lifecycle` 超时分支也置 `quitting`，并给 `applicationShouldTerminate_` 加绝对兜底次数；两个线程池在退出时 `shutdown(wait=False)`
2. **OAuth2 / Modern Auth**：至少支持 Gmail + Outlook365 的 XOAUTH2 授权流程，否则这条路会随时间彻底堵死
3. **IMAP IDLE**（或把默认轮询降到 60s 内）+ 单账号看门狗超时
4. **磁盘配额与回收**：本地数据体积上限 + 老备份自动清理 + 可选 VACUUM
5. **索引补齐**：附件名进 FTS；发件箱/草稿箱搜索改走后端索引
6. **universal2 构建 + 代码签名公证**
