# v4.1.1 附件完整性修复

- 基准版本：v4.1.0
- 变更类型：PATCH
- 目标版本：v4.1.1
- 判断依据：修复已有邮件收取功能在声明大小偏小时截断附件的问题；保留现有协议安全校验、资源上限、数据与配置兼容，没有新增功能或破坏兼容性变更。修订号由 0 升至 1，未触发编号进位。

当 IMAP 服务器声明的 RFC822.SIZE 小于实际 MIME 长度时，旧版下载达到该数值就停止，可能把照片的 Base64 数据截断。新版继续按有界片段读取到明确的空响应，独立检查实际接收字节上限，并让进度总量随实际长度修正。仍拒绝缺失、中断和超长分段响应，保留下载超时、重连、小邮件声明大小偏大的完整正文核对及 50 MB 自动收取上限。

Windows、macOS 和 Linux 使用相同的收取模块，本次同时修复三个桌面平台。合成多兆字节 MIME 回归逐字节核对原始邮件与解码附件，覆盖声明大小偏小、准确大小、偏大兼容、实际数据超限、下载中断和重试；Windows 安装包构建也执行该专项所在的完整离线门禁。正式发布须通过绑定候选 Git 树的完整验证、凭据扫描与各平台安装包检查。

不改变 Android 或 iOS 的独立版本号。已缓存的不完整邮件不会因升级自动补全；需要重新收取，或从完整原件恢复。本次用户报告的照片已在本机从 iPhone 完整原件恢复，并通过桌面下载接口逐字节核对；恢复不等于向服务器重新发送。
