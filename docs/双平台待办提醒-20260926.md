# 双平台待办提醒

## 用户流程

待办设置提醒 → 后台每 15 秒检查 → 系统通知与应用内提醒 → 待办中心的「提醒记录」查看所有邮箱 → 延后 10 分钟 / 明天 9 点 / 完成。

提醒记录保留每项任务最近一次安排及提交状态；完成、取消后可通过「显示已处理」查看。截止日期只标记逾期，不隐式开启提醒。计划编辑器提供快捷设置和「不提醒」。普通名称修改不会再提示重新设置提醒。

## 平台行为

- macOS 安装版：利用已有原生通知接口，通知携带任务信息；点击统一打开提醒记录，避免合并通知只展示第一项。
- Windows 安装版：沿用托盘系统通知，通过 Win32 `NIN_BALLOONUSERCLICK` 事件恢复窗口并打开提醒记录；托盘增加提醒记录入口。普通收信通知仍恢复主窗口。托盘通知没有持久的单条任务身份，不能承诺从旧系统通知精确跳到当时那条任务，列表提供兜底。
- macOS 源码启动：通过 AppleScript 提交系统通知，无原生窗口点击回调。通知记录提供手动入口。
- Windows 浏览器源码启动：没有桌面托盘运行时，不声称支持系统通知；保留应用内提醒。
- 完全退出或电脑关闭时不运行后台任务，下次启动补提醒。睡眠恢复后继续检查。
- 「已提交系统」仅表示通知接口接受，不代表系统实际展示或用户已读。通知权限、勿扰、专注模式仍由系统控制。测试入口明确提示检查设置。

## 稳定性

数据库按任务和提醒时间去重。发送前取得 60 秒租约，失败保留记录并重试，重启后不重复提交已接受的提醒。提醒时间修改后允许新一轮投递；完成清除提醒。与邮件同步调度独立，多个到期任务按账号合并。

## 验证与边界

- 本地全量离线检查 165 项通过；最后的提醒记录持久化调整另跑任务回归。
- Windows 壳层回归覆盖通知点击适配、托盘菜单保留、恢复窗口和前端入口（模拟 Win32 事件）。
- macOS 原生提交使用替身验证成功和失败返回、通知目标数据。
- 隔离浏览器验证安排、延后、测试通知入口、打开任务、完成后记录、暗色窄窗口和关闭；系统投递使用模拟，未发送真实通知。
- 当前主机不是 Windows；尚未进行 Windows 真机的通知权限 / 勿扰 / 操作中心保留行为验收。macOS 的系统权限和专注模式也仍需真实桌面验收，不能以自动化替身测试代替。
