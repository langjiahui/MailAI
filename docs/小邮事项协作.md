# 小邮事项协作

Web／桌面沿用现有收发、工作简报、会话进展和待办。Android、iOS 独立维护。

## 从沟通开始

打开邮件后点「问小邮」，可以先问“这封邮件要我确认什么”，也可以直接说自己的想法，先聊清立场、职责和需要回应的点，再准备回复。阅读区不常驻新增事项卡片；打开邮件和打开小邮欢迎页不会因此调用模型。

当你想保存背景时，可以说“我负责排期协调，帮我记住”。小邮先展示这条记录属于哪封邮件，经确认后保存；取消或保存失败都不会改动已有背景。临时说“这次正式一点”只用于本次沟通，不自动成为长期写作要求。说“以后回信简短一点”，确认后保存为当前邮箱的写作要求。

准备回复继续使用现有写信窗口。勾选「原邮件」可参考同一回复链的往来和已保存事项背景；「使用我保存的写作偏好」单独控制表达要求。生成后可点「核对回复是否答全」，检查原文问题遗漏和缺附件候选。核对不修改正文；修改正文或附件后，旧结果提示重新核对。

含 XLS、XLSX、DOCX、PDF 的邮件可使用原有[填写附件并回复](assistant-document-reply.md)流程。安排任务、提醒和查看会话进展沿用现有入口。发信跟进可准备保留回复关系的草稿，仍需核对后手动发送。工作简报先突出最多三件事项，点击进入对应邮件并与小邮讨论。

## 设置 → 小邮

「小邮」独立于常用设置和 AI 服务，包含两组：

- **沟通与记忆**：启用长期记忆、空闲整理对话、记忆摘要、管理记忆和清除对话记忆。
- **陪伴与外观**：小邮空间、主题兑换和轻动效，保留已有成长和装扮。

所有长期记忆和写作要求按邮箱隔离，摘要和管理窗口显示当前适用邮箱。关闭长期记忆会保留数据，停止在小邮问答和使用偏好的写作中引用长期内容，并停止经验分析。具体事项背景仍随当前邮件引用。

「管理记忆」分开显示已确认的写作要求与对话经验。经验包括写作要求、沟通方式、工作习惯、明确的长期职责与边界、通用术语与称谓。可按待确认、已采用、已停用查看，检查原话与对话来源，编辑、采用或停用单条记忆。

分析只读取新的用户发言，不把助手回答当作用户事实；项目人员、一次性要求、交期和某次立场不提升为长期信息。每批按时间顺序最多处理 80 条用户发言、16000 字，模型最多返回 8 条候选；长历史分批继续，不跳过早期记录。无新发言不调用模型。

空闲整理默认关闭；开启后，本窗口完成一次小邮沟通并空闲约 95 秒时尝试整理。服务端再次核对开关，只处理至少空闲 90 秒且已有助手回答的对话。分析与当前问答分开，结果先待确认，不会自行改写生效要求。模型不可用或分析失败不影响邮件操作，下次可手动分析。

清除对话记忆会移除当前邮箱的候选和已保存对话记忆，跳过清除前的旧对话，防止立即重新提炼同一批信息；已确认的写作要求、事项背景、邮件和聊天记录保留。写作要求可在管理窗口中单独清空并保存。停用单条写作记忆会移除对应要求，保留其他要求。删除聊天记录与删除长期记忆是独立操作。

## 处理与存储

参考 [OpenAI 官方 Codex 记忆说明](https://learn.chatgpt.com/docs/customization/memories)的分层和可控生命周期：明确要求、历史对话、归纳记忆各自管理；不读取 Codex 的本地记忆，也不假定其内部数据库实现。

MailAI 以每个邮箱原有 SQLite 数据库为唯一可信存储：

| 内容 | 数据表与规则 |
| --- | --- |
| 原始对话 | 现有 `assistant_conversations`、`assistant_messages`，保持原记录 |
| 邮件事项背景 | `work_context`，绑定邮件及编辑版本，永久删除邮件时随之清理 |
| 已确认写作要求 | `work_preferences`，兼容旧 `work_writing_preferences`，编辑检查版本 |
| 候选及已确认记忆 | `work_preference_candidates`，保存类别、状态、内容、原话来源及版本 |
| 引用与分析开关 | `work_learning_state`，使用单独版本使并发关闭或清除立即使旧分析失效 |
| 对话分析进度 | `work_memory_cursors`，每个对话独立推进；空闲过滤不会漏掉正在进行的对话 |

摘要从已确认记录即时生成，不再维护另一份可能失效的文本文件。记录随现有整库备份恢复；采用、停用和修改使用事务。并发旧窗口、清除期间返回的旧模型结果不能覆盖新状态。失败保留编辑内容并可重试。

## 效率与处理边界

- 邮件关联沿用回复邮件头，相同主题不自动合并。关联每次最多 100 封、12 轮展开；写作最多引用 12 封、22000 字正文及 5 条事项背景，达到上限会提示。
- 长期记忆只提供用户背景和表达要求，不构成邮件事实、审批授权、负责人认定或完成依据；本次明确要求优先。
- 回复语义核对需手动点击，最多并发两项、请求超时 45 秒。无模型仍可做本地缺附件检查。无候选不代表回复完整或事项完成。
- 来信、发送成功和“收到”都不代表交付完成，任务不会因此自动完成，也不会自动发送催办。
- 完成待办增加 12 成长度、6 邮票，每日最多奖励 10 项；同一待办永久去重。活跃每分钟、阅读每 30 秒各增加 1 成长度，普通点击不奖励。保留旧成长、邮票、装扮和领取记录。

## 验证

离线门禁登记 `test_work_assistant.py`、`test_work_memory.py`、`test_work_assistant_upgrade.py`。覆盖作用域、来源、并发保存、开关、清除后不重新学习旧对话、分批进度、空闲过滤、晚到分析、旧数据升级与备份恢复。浏览器用隔离合成邮箱验证 Chromium／WebKit 的对话、保存与重试、管理交互、主题、中英文、窄窗口及大字号。

实际业务中的回复采纳率、遗漏率和节省时间仍需使用评估，自动化检查不代表所有模型回答都准确。
