# 小邮套系收藏与旗舰设计

日期：2026-10-30。状态：设计提案及 Web／桌面首轮实现。概念图用于造型方向，运行资源采用原生分层 SVG；当前落地细节见文末。

## 当前判断

用户希望装扮形成系列，并在长期积累后得到完整成果；旗舰款需要在角色本身体现更高的设计完成度。

依据当前 Web / 桌面实现和 `output/xiaoyou-evolution/wardrobe-ranger.png`、`wardrobe-nature.png` 造型总览：

- `app/companion_growth.py` 中帽子、围巾、邮包、披肩、护目镜、轻甲和两种翅膀全部使用 `accessory` 位置，只能选择其中一件。这使“收集到一整套”和“穿出一整套”无法对应。
- `companion-growth.js` 的 `collectionView()` 以三个风格组织物品，但只预览代表单件，没有逐套归属、逐套进度或完成结果；现有总收藏数无法说明距离喜欢的完整造型还差什么。
- 现有高阶装扮在柔和蓝白配色、翼片和光效上相近，主要区别集中于局部。缩小到实际悬浮小邮后，区别可能进一步减弱，需在实机尺寸验证。

## 设计主轴

把“喜欢一个系列 → 得到第一件 → 一步步补全 → 穿出完整造型 → 留下完成纪念”做成清楚、可预览的旅程。

成长阶段、系列收藏、旗舰品质各自表达不同含义：成长决定小邮本身的生命形态；收藏记录用户获得的装扮；旗舰表示造型设计规格。旗舰需要适配不同成长阶段，不能只在第七阶段看起来完整，也不能覆盖小邮雀和小邮鱼的种族特征。

## 首批三个系列

先将三个系列做完整，再逐步增加新系列。每套确定共同的徽记、主色、辅色、材质和轮廓语言。

| 系列 | 美术语言 | 成套部件方向 | 完成后的视觉成果 |
| --- | --- | --- | --- |
| 晨光邮局 | 奶油白、邮政蓝、少量暖铜；织物、皮革、搪瓷邮徽 | 信使帽、围巾、邮包、系列配色 | 一眼可辨的完整小信使，帽徽、包扣和信封封签使用同一邮徽 |
| 云间远航 | 雾青、米白、蜂蜜金；帆布、皮带、轻盈羽片 | 护目镜、披肩、飞行背具、系列配色 | 户外探险的完整轮廓，背具与披肩有明确连接关系 |
| 星海巡邮 | 午夜靛蓝、珍珠白、香槟金；瓷釉面、金属包边、通透星图 | 额饰、胸甲、星图翼、系列配色 | 更开阔的左右轮廓，胸口星邮徽与翼面星图相互呼应 |

优先吸收现有物品，保留 ID、价格、所有权及历史礼券。普通星环、点点星光等通用光效继续自由搭配，不强制塞入每套，也不把成长莓或工作区主题计入套装完成条件。

现有物品只能作为素材起点；不能把当前几个互斥单件换上系列名称就视作完成设计。需要重新校准部件比例、颜色、连接点和同时穿戴后的遮挡。

## 穿戴结构

建议支持头饰、颈饰、身体／包具、背饰四个部位，另保留配色与环境光效。界面先展示完整搭配和系列，部位控制进入搭配详情后再展开。

- 帽子与护目镜先共用头饰位，避免头部过密；围巾使用颈饰位；邮包、披肩和轻甲使用身体位；两种翅膀使用背饰位。
- 每件定义占位和冲突规则。允许帽子＋围巾＋邮包一起穿，轻甲与翅膀一起穿；特殊整件造型可占多个部位，不能仅凭不同位置强行叠加。
- 新的整套穿戴一次校验所有权、冲突和部件有效性，再原子保存；操作中断后不能只穿上一半。未拥有全套时提供“穿戴已拥有部件”，缺件独立显示。
- 旧 `accessory` 根据物品 ID 映射到新位置，保留其他已穿戴配置；购买、赠礼、备份恢复和多窗口同步一起兼容。迁移不补扣邮票，不重新要求兑换。

## 让积累能被看见

装扮首页先展示正在收集的系列，其次展示其他系列，单品货架和自由搭配放在下方。用户可以选定一个收藏目标，目标只用于提示，不限制其他兑换。

每个系列卡片至少包含：完整造型、已收集／总件数、已拥有部件、缺少部件和最近可获得的一件。进度只计算本套唯一部件，重复领取不增加；不使用剩余邮票余额表示收藏进度。

以四件套为例：

1. 获得第一件：点亮系列页，出现自己的第一枚收藏邮戳。
2. 获得第二、三件：预览同步展示已经组成的搭配，缺件以单独图标列出；提供与下一件对应的真实成长／邮票差额。
3. 集齐四件：完整收藏邮戳落印，免费获得系列专属封签与一次完成动作，并可一键穿戴全套。

完成奖励由收藏状态确定，服务端校验，重复打开或重复同步不能重复发奖励。老用户已有物品自动计入，满足条件直接得到对应纪念。没有连续签到要求，不因中断使用撤回成果。

封签是角色信封上的小型系列标记，保存收藏身份；不强制绑定全套，不叠加多层光效。系列完成页可以保留完成日期，使收藏成为陪伴记录。

## 旗舰款的规格

首批将“星海巡邮”作为旗舰系列，集中精力做出明显层级。旗舰通过分件逐步完成；完整效果应在获得第一件前就能看到。

| 维度 | 旗舰要求 |
| --- | --- |
| 静态轮廓 | 即使暂停动画、去掉背景，也能通过额饰、肩部连接、翼尾关系辨识旗舰；不能只靠粒子和光晕 |
| 配色层次 | 用深靛与珍珠白建立明暗对比，金色只点在徽记和结构转折，保持脸部明亮 |
| 材质 | 明确区分釉面、金属边和半透明翼片，避免全身使用相似的浅色渐变 |
| 设计呼应 | 额饰、胸徽、翼片与信封共享同一星邮徽记，装饰围绕一个主题展开 |
| 两条路线 | 雀：有层次的展开羽翼、分叉流苏尾；鱼：流线鳍翼、星帆尾。保留鸟喙／鱼嘴、鸟足／鱼尾，不用同一副大翅膀遮住差异 |
| 动作 | 一次专属“封信—展翼—寄出星笺—回到待机”动作；待机只保留低频细节，表情和持信姿态仍然清晰 |
| 展示 | 独立的大幅全套试穿、部件分解与完成邮戳；货架卡片标识辅助说明品质，角色自身承担主要区别 |

在悬浮尺寸保留三个重点：头部识别点、胸口徽记、外侧翼尾轮廓。细星图和材质刻线留给大预览，避免在小尺寸变成噪点。信封始终是小邮的身份核心，旗舰仍是一位邮递伙伴。

## 落地顺序与验收

1. 先完成一个系列的双路线静态设计：单件、半套、全套，以及旗舰与普通款同尺寸对照。未经轮廓验证，不先增加特效。
2. 打通多部位与旧数据迁移，再接入系列归属、收藏进度和完成纪念。
3. 补齐整套试穿、拥有部件穿戴、完成动作；用同一套资源覆盖悬浮、聊天、写信和手账。

视觉验收：原有小邮约 80px 场景、预览大图、明暗主题、七阶段及两条路线均有可读的外观；静态下可区分普通与旗舰；部件组合不遮眼、不遮信封、不悬空，左右肩连接自然。

行为验收：旧库存和礼券保留、重复兑换不重复扣款、全套穿戴原子提交、刷新与多窗口一致；缺件和阶段门槛提示准确，试穿不改变真实装备与成长。

能耗验收：沿用矢量分层和现有节能调度，后台、离屏、轻动效及系统减少动态效果仍生效；完成动作一次播放，静态旗舰造型独立成立。

本提案不调整应用版本，也不构成发布。后续新增多部位穿戴和收藏能力属于兼容新功能，正式发布时按各端最近正式版本及本次完整变更独立分级。


## 首轮实现范围

已实现小邮空间的分区导航、常驻角色、独立试穿、响应式分页衣橱与单阶段进化查看；多部位穿戴兼容旧库存及礼券。首批套系使用 3／3／4 件构成，旗舰新增星邮额饰，保留旧部件价格。完成奖励为收藏邮戳、整套穿戴的信封封签及一次纪念寄信动作，不新增货币或连续签到条件。Android 原生界面未在本轮改动，后续应沿独立版本线适配。
