# 模型 API 接入

设置 → 数据与维护 → 管理员高级配置 → 模型 API。

选择服务商、填写开放平台 API Key、核对模型名称，测试连接成功后保存。修改立即生效于后续请求。只维护一套当前生效的连接；切换地址或服务商须重新输入对应 Key，同一连接留空可保留已有 Key。测试草稿不保存配置，也不会发送邮件内容；会发送一条“只回复 OK”的请求，可能产生少量费用。

- 自部署 / 其他兼容服务：保留原部署配置；支持 OpenAI Chat Completions 格式、Bearer Key、普通 JSON 与 SSE。可填写根地址、以 /v1 结尾的地址，或完整 /chat/completions 地址。其他版本和厂商特殊路径请填完整接口地址，如 https://example.com/api/v4/chat/completions。不是原生 Anthropic Messages、Gemini generateContent 或 Responses 协议适配器。
- DeepSeek：预设 https://api.deepseek.com/v1，deepseek-v4-flash。V4 默认关闭思考以适配邮件分析的输出预算，图片识别默认关闭。其他可用模型按开放平台填写。
- Kimi：预设 https://api.moonshot.cn/v1，kimi-k2.6，关闭思考且省略不支持的 temperature；图片识别默认开启。国际站或代理须更改对应地址与 Key。K3 等强制思考模型可能需要更高输出预算，预设选择可关闭思考的 K2.6。

图片模型与文本模型共用 API 地址及 Key。只有支持图片输入的模型才能开启图片识别；关闭时图片分析会明确提示，文本分析仍可用。

扩展参数填写 JSON 对象，通常保持 {}。可按厂商要求添加 enable_thinking 等字段；null 表示省略该参数。不能覆盖 model/messages/stream/api_key/base_url。扩展参数同时用于普通与流式调用，切换厂商会清空旧参数。若自行启用思考，需按厂商要求调整 max_tokens 和等待预算，否则可能出现输出不完整。

配置继续保存在本机现有配置文件，不会嵌入默认分发包的 API Key。旧配置默认归为“自部署 / 其他兼容服务”，不自动改写地址、模型或既有扩展参数。

## Kimi Code 补充验证

用户确认此前 Key 属于 Kimi Code。其专用接口是 https://api.kimi.com/coding/v1，模型 kimi-for-coding；不能使用普通开放平台地址验证该 Key。新增独立的“Kimi Code（编程订阅）”选项，并省略 temperature，保持服务端默认参数。图片能力未实测，因此该预设默认关闭图片识别。

经用户授权实测：普通连接 HTTP 200、回复 OK；JSON 模式返回 {"ok":true}；流式回复 OK。测试通过 MailAI 的调用层，无需伪装其他客户端，也未保存 Key、发送邮件内容或修改当前生效配置。DeepSeek Key 此前也已验证返回 OK。

## 通用厂商入口

新增独立“其他厂商（通用 API）”（provider=other），与“自部署模型”（原 custom）分开显示。选择其他厂商后，地址、模型和密钥输入清空，支持自由填写完整 Chat Completions 接口或基础 /v1 地址，以及 JSON 扩展参数。普通与流式请求共用兼容层，不代表原生支持所有厂商私有协议。离线测试验证了自定义兼容路径、模型 ID、参数透传和省略参数；界面实测验证了选项与表单清空。
