# MailAI 稳定性与资源专项体检

版本：1.20260906.2800（macOS arm64）

## 结论与范围

针对异常循环、内存持续增长、CPU 占用和崩溃路径完成代码加固、隔离回归、浏览器短时压力观察。已发现的问题已修复；本轮没有发现持续增长或空闲忙循环的证据。

这不是零崩溃保证。315 秒的本地观察不能替代数日运行、睡眠唤醒、真实弱网、大附件、不同 macOS 版本和多用户模型并发验收。本轮不操作真实邮箱、不向联系人发测试邮件、不调用真实模型做压力测试。

## 修复项

1. **正文尺寸反馈循环**：不再用上一次 iframe 高度参与下一次高度累加；固定基准测量，忽略自身布局产生的重复通知。对于 `vh`、百分比布局及极长邮件，必要时允许内部滚动，不无限扩大阅读页面。
2. **已关闭正文占用资源**：切换邮件时清理正文 ResizeObserver、待执行动画帧和图片监听；统一追踪存活正文，移除后释放引用。
3. **慢同步轮询叠加**：同一监控只允许一个在途请求；停止或切换账号中止旧监控，旧响应不能更新新账号。只读 API 增加 20 秒超时并清理信号监听；发信、移动等写操作不因该超时而被自动重试。
4. **AI 逐 token 重建页面**：将 Markdown/表格渲染合并为约 120 毫秒一批；结束、取消和失败时清理刷新计时器。限制过大回复和不正常的响应缓冲，防止页面一直累积文本。
5. **模型无限响应**：按块读取，设置总响应字节、单行字节、输出字符及时间边界；收到明确结束标记即停止。总时间检查在读取块之间进行，单次阻塞读取另受网络超时限制，不承诺在某一毫秒精确停止。
6. **提醒检查读取完整邮箱正文**：通知只流式读取新增邮件的必要字段；小邮风险提醒和结构化检索先读取轻量元数据，只为最终入选邮件读取正文；提醒状态未变化时不重复写数据库。
7. **大邮箱启动修复内存峰值**：历史正文修复改为按 ID 分批读取、每批关闭数据库连接；简报只读取实际关联旧待办的邮件，不加载整个邮箱再筛选。
8. **收信时整批原文驻留内存**：新邮件和历史邮件用有长度的 UID 计划逐封读取；服务端文件夹同步也逐封获取缺失原文。每次重新定位原文件夹，防止前一封邮件的移动改变 IMAP 当前文件夹。历史处理顺序与失败后重试规则保留。
9. **后台发件任务重复启动与失败循环**：启动加锁保证单实例；账户失败采用 5 秒起、最高 300 秒的退避；注册表故障延后重试而不是永久退出。每轮最多处理一个账号的 10 个到期任务，其他账号仍有机会执行；清理已删除账号的工作缓存。发送结果不确定时仍不自动重发。

## 实测证据

| 检查 | 结果 |
| --- | --- |
| 全量离线回归 | 79/79 检查命令通过 |
| 真实 Chromium 功能回归 | 11 组通过，无未处理 JS 异常 |
| 正文压力测试 | 连续挂载/移除 200 次，存活正文追踪归零；GC 后 JS 堆从 2.44 MiB 降到 2.19 MiB |
| 慢轮询 | 模拟 200 次计时触发，实际只有 1 个在途请求；账号变化后不应用旧响应 |
| 315 秒界面观察 | 165 次邮件切换、15 轮设置页访问；宠物动画及后台轮询开启 |
| 空闲页面 CPU | 约 0.26% 单核，按 Chromium TaskDuration / 时间差计算；不是整个桌面 App 的总 CPU |
| 空闲页面内存 | GC 后 JS 堆 3,494,272 → 3,526,776 字节，增加约 32 KiB 后稳定；DOM 节点保持 5827 |
| 测试后端 | 空闲采样 RSS 60,400 → 60,880 KiB，CPU 多数 0.0–0.5%；采样最高约 1.3% |
| 大邮箱提醒 | 2000 封，每封正文/HTML 合计 64 KiB；原完整读取分配峰值 137,804,778 字节；改后 30 轮提醒检查峰值 1,811,002 字节，约 0.84 秒 |
| IMAP 惰性读取 | 1000 封 UID 不预下载原文，每次 BODY 请求仅 1 封；模拟处理中切换到隔离文件夹，后续读取仍定位回 INBOX |
| 后台任务 | 20 个并发启动请求只有一个发件线程；断开账户按退避重试，不阻塞健康账户；25 项发送任务分批执行 |
| 模型边界 | 无换行超大数据、超大响应、过期响应、连续超长文本均终止，响应资源关闭 |

内存指标分别来自浏览器 GC 后堆统计、`ps` RSS 和 Python `tracemalloc`，不能互相等同；模型/邮件服务器以隔离替身验证，不代表真实服务器负载结果。

## 试用发布

安装包为 `dist/MailAI-macOS-arm64-1.20260906.2800.pkg`。实际打包程序通过空数据目录启动、健康接口、静态资源和本机来源限制检查；App 内部签名完整性验证通过。

沿用已授权的共享模型密钥，仅供受控内部试用，不带邮箱账号或邮件数据库。PKG 仍未进行 Apple Developer ID 签名/公证，不宜公开分发。生成的临时默认配置在打包后删除，原 `.env` 保留。

建议先用少量专用测试账号做真实收发、断网重连、退出再启动与一整天运行观察，再逐步扩大试用。
