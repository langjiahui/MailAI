# MailAI iOS

目标版本 **1.0.0**，当前处于首版测试验收，尚未发布 iOS 正式版。最低 iOS 18，支持 iPhone 和 iPad 的 arm64 真机；iPhone 15 Pro 可用。

SwiftUI 原生客户端，手机直接通过 IMAP / SMTP 收发邮件，不需要电脑或 Web 服务在线。邮件协议使用固定修订的 SwiftMail 1.16.0。Android、Web/桌面和 iOS 各自独立维护版本。

## 本地升级候选（开发验收中）

默认采用宝武蓝 `#005EAA` 与蓝白界面，深色模式使用对应的蓝色强调与深色背景，默认跟随系统；支持外观与正文字号设置。收件箱、邮箱/文件夹、阅读、写信、通讯录和设置重新组织。

收件箱不再常驻底部导航。左上角头像打开邮箱与文件夹面板，面板底部进入通讯录或设置；返回后保留当前邮箱及筛选。顶栏提供搜索和写信图标，文件夹标题菜单提供草稿、会话显示与批量整理。搜索栏与单一筛选入口属于邮件列表，随滚动移出屏幕，回到顶部重新出现；启用筛选后可点击条件标签清除，顶栏同时显示当前条件。批量工具栏与撤销提示仅在相应操作时显示。

收件箱列表使用发件人字母／汉字头像、发件人／主题／已有摘要的文字层级；仅邮件头的条目保持两行紧凑布局。列表搜索框滚出屏幕后，顶部显示搜索图标；固定顶部布局与点击区域，避免重复入口。顶部图标保持 44 pt 点击区域，按下有底色、缩放与轻触反馈，并遵循减少动态效果偏好。

阅读器会将桌面固定宽度的 HTML 邮件整体缩放到正文宽度，完整保留二维码、右侧文字和按钮；支持双指放大查看与拖动，跟随深色主题，仍禁用发件人脚本与外部资源。原始样式和纯文本入口保留。

邮件发件信息旁及联系人详情提供“往来邮件”。按当前邮箱的发件人／收件人／抄送地址精确查找收件、已发送及归档等文件夹，排除草稿、废纸篓和垃圾邮件；先展示本机缓存，再逐文件夹查询，可停止、重试及加载更多（每文件夹最多 500 封）。打开历史邮件不改变原收件箱位置；邮箱切换时取消旧查询，缓存按账号隔离。已发送邮件入口默认查找与首位其他收件人的往来。

仅配置一个邮箱时，往来邮件和通讯录不重复显示当前账号，搜索只显示文件夹范围；多邮箱时显示账号上下文。往来邮件页面支持勾选、全选已加载、批量移入废纸篓，以及“仅对方发来的邮件”筛选。“加载并选择全部往来”按 UID 分页继续查询早期记录，不受单文件夹 500 封展示上限限制；查询失败或停止时不自动声称已选全部。同一 Message-ID 的文件夹副本在列表合并展示，删除确认写明邮件数及文件夹记录数，按原文件夹分批移动；只有全部成功且 UID 映射齐全时提供短暂撤销。部分结果未确认时停止后续操作并要求刷新核对，避免重复删除。新到邮件不包含在已确认的选择快照内。

批量删除：文件夹标题菜单中点“选择邮件”，或长按邮件点“选择并批量操作”，勾选后点“删除”。确认具体数量后移到废纸篓，取消不执行操作；服务器返回完整 UID 映射时提供短暂撤销。无法识别废纸篓时让用户明确选择文件夹，不直接永久删除。

候选代码新增：附件下载/预览/分享与文件/照片发送；抄送/密送、回复全部和转发；多草稿与发送记录；服务器已读/星标/移动、归档和移至废纸篓；整个当前文件夹的服务器搜索、短暂撤销（移动须有服务器确认的 UID 映射）；多个账号缓存组成的统一收件箱、基于回复标识的会话聚合；按账号隔离的往来联系人与系统单个联系人选择；已有账号重新验证、签名和已发送副本设置。

附件单个 15 MB、合计 25 MB、最多 20 个，发送前校验并从受保护的独立文件读取。相册照片保留实际传入的原始编码，按文件内容识别扩展名与 MIME；拒绝空数据、损坏图片和缺少结束标记的 PNG，避免将可用格式误标成其他图片格式。转发正文和转发全部附件为不同的明确操作；下载不完整时不静默转发。历史单草稿自动迁入草稿列表，保留发送结果未知时的重发锁定。SMTP 接受后与已发送副本存档分别处理，后者失败只能重试存档，不重新提交 SMTP；通过稳定 Message-ID 查询去重。Gmail/Outlook 默认依赖服务商保存，其余默认客户端保存，支持用户调整。

小邮按需提炼要点、提取待办、翻译、起草回复和润色，使用用户配置的 HTTPS Chat Completions 兼容服务。配置/密钥存钥匙串；需明确授权邮件文字发送范围。仅主动调用，不上传整箱与附件；结果完整后才允许采用，润色核对原草稿版本并可撤回。取消、退后台不采用半成品。

新邮件提醒采用系统后台刷新与本地通知，默认关闭。在“设置 → 后台收信与通知”开启后申请系统权限，为后台收信单独复制必要的账号凭据，采用 AfterFirstUnlockThisDeviceOnly；独立提醒状态文件采用首次解锁后可读的保护。原账号凭据、模型密钥、正文、附件与草稿保留原有锁屏保护；关闭提醒即取消任务并清理后台凭据与提醒状态。重启后需先解锁一次；iOS 决定后续运行时间，低电量、系统后台 App 刷新关闭、公司网络／VPN 不通或强制退出都可能推迟或阻止检查。免费个人签名没有 APNs 权限，本次按用户选择完善“可能延迟”的系统后台提醒，不宣称即时推送。

前台每分钟检查邮件头，后台由 BGAppRefreshTask 检查最新 200 封元数据，不取正文、附件，不运行小邮。首次检查（包括空收件箱）建立基线；后续按账号、UIDVALIDITY、UID 去重，只提醒新到未读邮件，文件夹重建重新建立基线。提醒提交前先持久化待发队列，系统提交失败保留队列重试；单账号失败不阻止其他账号。默认提醒隐藏姓名／主题，可选择显示；关闭预览会清理排队预览与已显示提醒。点通知保存草稿后打开对应账号和 UID，目标失效时回到收件箱核对，避免打开错信。

通知页提供权限、系统后台 App 刷新、低电量状态、立即检查和 10 秒测试提醒。测试提醒只证明展示通道，不代表真实收信或系统后台调度成功；立即检查与最近系统后台检查分别记录，取消／过期不记成功。用户确认本次不需要 Google/Microsoft 网页授权登录。

钥匙串与本机缓存继续使用设备专属访问及文件保护；TLS/证书核对不降级，正文禁止脚本及外部网络资源。API Key 不随 HTTP 跳转发送，不把模型响应或服务错误正文写入日志。功能是否完成验收以最新 CI 与设备验收记录为准，代码存在不代表已安装。

## 添加邮箱体验优化（待发布）

添加页默认只需邮箱地址与密码／授权码，登录用户名自动跟随邮箱地址，显示名称和收发服务器收进可选高级设置。QQ／Foxmail、163／126／yeah、iCloud、Gmail、Outlook、Yahoo、阿里云、新浪、搜狐与 139 的服务器预设与 Web 端一致；未知域名默认建议 `imap.<域名>:993`、`smtp.<域名>:465`（TLS），标明为域名推测。用户点击添加后才验证 IMAP 与 SMTP 登录，失败保留输入并可修改高级设置；未知域名连接失败时自动展开高级设置。

编辑服务器后保留手动配置；更换邮箱域名时重新匹配，避免沿用前一个服务商的主机、端口或加密方式。高级设置支持恢复自动服务器配置。没有自动尝试多个主机或降低证书验证。Google／Microsoft 网页授权尚未移植，预设服务器不代表账号允许密码登录；界面按服务商提示应用密码或授权限制。

## 公司内网邮箱连接（本地修复候选）

用户配置的邮箱服务器支持私网 IPv4、运营商内网和 IPv6 ULA，也支持公司内网域名；环回、链路本地、组播、未指定和无效地址仍拒绝。TLS 1.2+／强制 STARTTLS 和完整证书验证保持启用，IP 地址必须匹配证书中的 IP SAN；不能用“忽略证书”代替正确的企业证书配置。

不以公网是否可用来判定公司网络在线，不强制绕过 VPN 绑定 Wi-Fi。初次 TCP／TLS 握手失败时，先通过系统 Network.framework 等待目标服务器的网络路径和首次本地网络授权，再只重试一次握手；不重试登录、邮件提交或不确定发送。正常连接不会增加额外探测，取消账号验证会终止等待。权限、DNS、不可达、超时和端口拒绝分别给出处理提示，添加、刷新、阅读及发送保留这些提示；缓存与草稿继续保留。

公司域名的自动服务器地址仍是建议，须与管理员提供的 IMAP／SMTP 配置一致。首次访问内网请允许本地网络权限；若已拒绝，可到“设置 → 隐私与安全性 → 本地网络 → MailAI”开启。公司 Wi-Fi 或 VPN 及企业 CA 的真机配置仍需现场验收。

邮件列表遇到服务器元数据语法错误时，会在新建、完整验证证书的连接上依次改用轻量元数据、原始邮件头读取，并在本次进程内记住成功方式；不会对登录错误、解析资源上限或邮件写操作自动重试。兼容模式中的附件图标可能要打开邮件后才能确认，正文和附件仍按需读取。成功刷新会清除旧的收信错误，不影响其他操作提示。诊断只在设备缓存保留最近一次失败阶段、固定错误分类和解析器源码位置，不记录服务器地址、账号、密码或邮件内容。

## 构建与安装

需要完整 Xcode（Swift 6.2+）、XcodeGen 和 iOS SDK：

```sh
cd mobile/ios
swift test
python3 scripts/build.py
```

生成 `build/distribution/MailAI-iOS-1.0.0-unsigned.ipa`、SHA-256 和构建清单。该 IPA 是真实 arm64 应用，但**未签名，不能直接安装**。可使用用户已有的设备证书在签名工具中签名安装，详见 [安装说明](INSTALL.md)。CI 还执行模拟器启动与账号表单 UI 测试，保留结果包和截图。

本地正文修复可手动运行 `ios-preview.yml` 并选择 `verification=reader`：构建真机 IPA，执行实际 WebKit 正文配色、深浅色旧式 HTML、外部链接确认和纯文本切换的专项验证，生成对应截图。产物中的 `validation-scope.json` 会明确记录 `reader` 范围，不能作为全量原生验证或正式发布凭证。默认值、PR 和发布分支仍执行 `full`，保留全部原生测试矩阵。

版本：`VERSION` 是 iOS 产品版本，`BUILD_NUMBER` 是本地内部构建号，`project.yml` 必须一致。CI 的内部构建号使用该工作流 run number × 100 + run attempt；重试不递增产品版本。测试标签为 `ios-v1.0.0-beta.N`，正式标签为 `ios-v1.0.0`；iOS 发布不改变 GitHub 的桌面 Latest 入口。正式发版前须通过根发布门禁、iOS 测试、构建与目标设备签名安装验收。

## 首版版本判断

- 基准版本：无，仓库及 GitHub 尚无独立 iOS 正式发布。
- 变更类型：首次建立 iOS 原生产品线。
- 目标版本：1.0.0；验收阶段使用 1.0.0-beta.N 发布标签。
- 判断依据：新增独立运行的 iOS 客户端，不继承 Android 1.3.3 或 Web/桌面 2.10.2 的编号；后续以 iOS 自己的最近正式版按 MAJOR / MINOR / PATCH 分级。

HTML 正文默认跟随系统外观：深色下适配旧式黑字、表格底色和边框，保留图片与强调色，并检查文字对比度；“更多邮件操作 → 查看原始样式”可切回发件人的原始配色，“跟随系统主题”恢复适配。配色脚本仅由应用在隔离环境执行，邮件自身脚本保持禁用。

阅读页不再常驻“小邮／提炼要点”入口或预留整行空间；“小邮助手”收进右上角“更多邮件操作”菜单末尾，需要时再打开。正文紧接发件信息，默认专注阅读。
