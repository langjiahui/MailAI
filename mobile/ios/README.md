# MailAI iOS

目标版本 **1.0.0**，当前处于首版测试验收，尚未发布 iOS 正式版。最低 iOS 18，支持 iPhone 和 iPad 的 arm64 真机；iPhone 15 Pro 可用。

SwiftUI 原生客户端，手机直接通过 IMAP / SMTP 收发邮件，不需要电脑或 Web 服务在线。邮件协议使用固定修订的 SwiftMail 1.16.0。Android、Web/桌面和 iOS 各自独立维护版本。

## 本地升级候选（开发验收中）

默认采用宝武蓝 `#005EAA` 与蓝白界面，深色模式使用对应的蓝色强调与深色背景，默认跟随系统；支持外观与正文字号设置。收件箱、邮箱/文件夹、阅读、写信、通讯录和设置重新组织。

收件箱不再常驻底部导航。左上角头像打开邮箱与文件夹面板，面板底部进入通讯录或设置；返回后保留当前邮箱及筛选。顶栏提供搜索和写信图标，文件夹标题菜单提供草稿、会话显示与批量整理。搜索栏与单一筛选入口属于邮件列表，随滚动移出屏幕，回到顶部重新出现；启用筛选后可点击条件标签清除，顶栏同时显示当前条件。批量工具栏与撤销提示仅在相应操作时显示。

候选代码新增：附件下载/预览/分享与文件/照片发送；抄送/密送、回复全部和转发；多草稿与发送记录；服务器已读/星标/移动、归档和移至废纸篓；整个当前文件夹的服务器搜索、短暂撤销（移动须有服务器确认的 UID 映射）；多个账号缓存组成的统一收件箱、基于回复标识的会话聚合；按账号隔离的往来联系人与系统单个联系人选择；已有账号重新验证、签名和已发送副本设置。

附件单个 15 MB、合计 25 MB、最多 20 个，发送前校验并从受保护的独立文件读取。转发正文和转发全部附件为不同的明确操作；下载不完整时不静默转发。历史单草稿自动迁入草稿列表，保留发送结果未知时的重发锁定。SMTP 接受后与已发送副本存档分别处理，后者失败只能重试存档，不重新提交 SMTP；通过稳定 Message-ID 查询去重。Gmail/Outlook 默认依赖服务商保存，其余默认客户端保存，支持用户调整。

小邮按需提炼要点、提取待办、翻译、起草回复和润色，使用用户配置的 HTTPS Chat Completions 兼容服务。配置/密钥存钥匙串；需明确授权邮件文字发送范围。仅主动调用，不上传整箱与附件；结果完整后才允许采用，润色核对原草稿版本并可撤回。取消、退后台不采用半成品。

系统后台刷新和本地提醒默认关闭，需用户启用；iOS 决定调度时间，不能保证固定间隔或即时提醒。锁屏钥匙串可能不可读，失败不写成功记录。通知首次建立基线，不提醒历史邮件。本轮不接入 APNs 服务端推送；用户确认本次不需要 Google/Microsoft 网页授权登录。

钥匙串与本机缓存继续使用设备专属访问及文件保护；TLS/证书核对不降级，正文禁止脚本及外部网络资源。API Key 不随 HTTP 跳转发送，不把模型响应或服务错误正文写入日志。功能是否完成验收以最新 CI 与设备验收记录为准，代码存在不代表已安装。

## 添加邮箱体验优化（待发布）

添加页默认只需邮箱地址与密码／授权码，登录用户名自动跟随邮箱地址，显示名称和收发服务器收进可选高级设置。QQ／Foxmail、163／126／yeah、iCloud、Gmail、Outlook、Yahoo、阿里云、新浪、搜狐与 139 的服务器预设与 Web 端一致；未知域名默认建议 `imap.<域名>:993`、`smtp.<域名>:465`（TLS），标明为域名推测。用户点击添加后才验证 IMAP 与 SMTP 登录，失败保留输入并可修改高级设置；未知域名连接失败时自动展开高级设置。

编辑服务器后保留手动配置；更换邮箱域名时重新匹配，避免沿用前一个服务商的主机、端口或加密方式。高级设置支持恢复自动服务器配置。没有自动尝试多个主机或降低证书验证。Google／Microsoft 网页授权尚未移植，预设服务器不代表账号允许密码登录；界面按服务商提示应用密码或授权限制。

## 构建与安装

需要完整 Xcode（Swift 6.2+）、XcodeGen 和 iOS SDK：

```sh
cd mobile/ios
swift test
python3 scripts/build.py
```

生成 `build/distribution/MailAI-iOS-1.0.0-unsigned.ipa`、SHA-256 和构建清单。该 IPA 是真实 arm64 应用，但**未签名，不能直接安装**。可使用用户已有的设备证书在签名工具中签名安装，详见 [安装说明](INSTALL.md)。CI 还执行模拟器启动与账号表单 UI 测试，保留结果包和截图。

本地正文修复可手动运行 `ios-preview.yml` 并选择 `verification=reader`：构建真机 IPA，执行实际 WebKit 正文配色、深浅色旧式 HTML、外部链接确认和纯文本切换的专项验证，生成对应截图。产物中的 `validation-scope.json` 会明确记录 `reader` 范围，不能作为全量原生验证或正式发布凭证。默认值、PR 和发布分支仍执行 `full`，保留全部原生测试矩阵。

版本：`VERSION` 是 iOS 产品版本，`BUILD_NUMBER` 是本地内部构建号，`project.yml` 必须一致。CI 的内部构建号使用该工作流 run number × 100 + run attempt；重试不递增产品版本。测试标签为 `ios-v1.0.0-beta.N`，正式标签为 `ios-v1.0.0`；iOS 发布不改变 GitHub 的桌面 Latest 入口。正式发版前须通过根发布门禁、iOS 测试、构建与目标设备签名安装验收。

## 首版版本判断

- 基准版本：无，仓库及 GitHub 尚无独立 iOS 正式发布。
- 变更类型：首次建立 iOS 原生产品线。
- 目标版本：1.0.0；验收阶段使用 1.0.0-beta.N 发布标签。
- 判断依据：新增独立运行的 iOS 客户端，不继承 Android 1.3.3 或 Web/桌面 2.10.2 的编号；后续以 iOS 自己的最近正式版按 MAJOR / MINOR / PATCH 分级。

HTML 正文默认跟随系统外观：深色下适配旧式黑字、表格底色和边框，保留图片与强调色，并检查文字对比度；“更多邮件操作 → 查看原始样式”可切回发件人的原始配色，“跟随系统主题”恢复适配。配色脚本仅由应用在隔离环境执行，邮件自身脚本保持禁用。

阅读页不再常驻“小邮／提炼要点”入口或预留整行空间；“小邮助手”收进右上角“更多邮件操作”菜单末尾，需要时再打开。正文紧接发件信息，默认专注阅读。
