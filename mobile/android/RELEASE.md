- 日期：2026-10-19
- 基准版本：GitHub 最近正式版本 v2.9.4；最近 Android 预发布 2.10.0-beta.4。
- 变更类型：本轮相对 beta.4 为 PATCH 类兼容性修复；从正式 v2.9.4 起的 Android 整体为 MINOR。
- 目标版本：Android 2.10.0-beta.5；versionCode 2100005；标签 android-v2.10.0-beta.5。
- 判断依据：修复既有后台收信、通知去重与通知跳转，完善状态提示，没有新增独立产品能力。Android 目标正式版本仍为 2.10.0，递增测试序号；根 VERSION 与桌面 Latest 保持 2.9.4。已发布标签及安装包不变。

## 本轮修复

- 系统通知权限或渠道关闭时，待通知记录留在数据库；恢复允许后补发，已读邮件从待处理队列移除。只确认实际提交给系统的那批记录。
- 同一账号沿用一张通知卡片，同一批次重试不重复响铃；新到邮件更新卡片并正常提醒。首次同步不通知历史邮件，账号和 UIDVALIDITY 继续独立处理。
- 点击通知直接打开对应账号和邮件；多封合并打开该批最新邮件。目标不在本地列表时明确提示并提供刷新，不误开别的邮件；跳转前保存编辑中的草稿。
- 返回应用会补查过期或失败的收信，并尝试提交待处理通知；近期成功的账号避免再次连接。后台网络条件不再依赖系统联网探测成功，实际邮箱仍执行公网地址和 TLS 校验。
- 设置页显示当前省电状态、后台电池设置入口和收信限制。默认通知不显示发件人与主题；开启预览后，锁屏内容遵循系统隐私设置。

## 使用边界

Android 10+。后台收信是系统周期检查，不是即时推送：深度省电可能延迟，强行停止后需再次打开应用。模拟器采用加速状态切换验证，不等同实体手机过夜实测；厂商省电策略、真实邮箱和耗电仍需验收。

通知提交与本地队列确认无法形成跨系统事务；如果进程恰好在两者之间终止、同时原通知又被清除，不能承诺严格一次送达。原卡片仍存在时会静默更新，已确认批次不会重发。最新窗口以外的大批历史邮件仍不保证逐封提醒。

所有邮件测试使用本地合成数据，没有向外部收件人发送邮件。安装包、更新清单、SHA-256、说明与验收记录发布到 GitHub 预发布通道，不含凭据或真实邮件。beta.4 可直接覆盖升级。
